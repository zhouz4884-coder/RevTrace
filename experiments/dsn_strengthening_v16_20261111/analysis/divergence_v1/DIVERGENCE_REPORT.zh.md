# 分歧机会审计 v1：0 分歧是"没分歧"还是"没机会"

2026-11-11。**纯 CPU 只读重算**，输入全部为已冻结的 JSON 产物，不触发模型、不读 GPU、不重扫原始日志。

## 0. 为什么要算这个

v16 pilot 报告了一个结论：`dependency_versioned` 与 `fullcall` 在 24 格里期限信用完全相同（32.340125 audio-s），且 `ancestor-only` 独特分歧为 0。

一个 0 可以有两种完全不同的含义：

- **(i) 两个策略看了同一个局面，做出了相同决定** → 这是"等价"的证据；
- **(ii) 能区分它们的局面从未出现** → 这是"没测到"的证据，什么也不能推出。

审稿人和后续决策（是否放弃机制主张）取决于 (i) 还是 (ii)。本审计把**分歧率的分母**算出来。

## 1. 两条判据的可分辨位置

| 策略 | 保留条件 | 它的判据在什么事件上才会与对方不同 |
|---|---|---|
| `fullcall` / RevTrace | 完整原始输入仍被确认（EL over complete input） | 输入失效但版本仍是相容祖先 |
| `dependency_versioned` | 出生版本是被采用父状态的直接相容祖先（版本级证据） | 祖先已被反证但完整输入仍合法 |

因此分歧只可能落在两个象限：**(祖先反证 ∧ 输入合法)** 或 **(祖先未反证 ∧ 输入失效)**。其余情形两条判据必然同判。

## 2. Part A：24 格 pilot 的 290 个决策点

| 祖先反证 | 输入状态 | fullcall 保留 | dep 保留 | 事件数 |
|---|---|---|---:|---:|---:|
| 否 | 已确认 | 是 | 是 | **278** |
| 否 | 起点已被反证 | 否 | 否 | **12** |
| 是 | 任意 | — | — | **0** |

- 决策点合计 **290**，`treatment_disagreement` = **0**。
- **祖先反证 = 0**：整个批次没有任何一次 install 让某个在飞调用的冻结祖先失效。
- **UNKNOWN / pending 输入 = 0**：没有任何一次判定发生在"输入尚未确定"的状态下。
- 全批 24 格的必要不兼容撤回 = 0，可避免损失 = 0。**没有撤回，就不可能有祖先反证**——这两个零是同一个事实。

**读法**：pilot 的 0 分歧属于 (ii)。不是两个策略同意了，是能分开它们的条件在这批轨迹里不存在。

## 4. 交叉验证（独立于本审计）

本审计的预测：若间隔恒为 1，则要求间隔 = 0 的**严格出生版本策略必然一次都晋升不了**。

机会审计的实测（`OPPORTUNITY_AUDIT_REPORT_V1.zh.md` 第 2 节）：Strict-birth 辅助臂 `实际 recorded promotions = 0`。

**两套独立计算互相印证。** 这也顺带解释了为什么 `safe_versioned` 的期限信用与 `Conservative` 完全相同（12.000000 / 12.000000）：它要求间隔 0，而真实轨迹恒为 1，于是它丢掉了全部 69.017 s 合法计算，退化为不保留。

## 5. 为什么间隔恒为 1（不是巧合）

7 次调用的 `model_seconds` 超过 1.0 s（即超过两个 500 ms 前沿），间隔仍然是 1。所以**慢模型本身不会造成跨代**：采用点被钉在该调用自己的 frontier 上，而不是钉在"最新的 frontier"上。

于是间隔 ≥ 2 的必要条件是：**某个 frontier 被跳过或被弃用**——例如一次 install 之后没有产生可用后继，或某个结果作废后由补算填位。当前实现里这两种情况都由**重算补位**消化掉了：链始终是满的 17 个状态、无空洞。

**结论：间隔恒为 1 不是这批样本的偶然，而是"重算保证规范链无空洞"的直接推论。** 只要规范链无空洞，"版本 ≠ 爸爸"就必然等于"爸爸是直接前驱"，版本级判据因而在构造上足够。

## 6. 可以主张什么，不可以主张什么

**可以主张：**

1. 在 24 格 pilot 的 290 个决策点上，两条判据的可分歧象限出现 **0** 次；这是机会缺失，不是判断一致。
2. 在 4 源 92 次真实跨版本保留上，版本间隔 **92/92 = 1**，占用 69.017 worker-s，无一次跨代或离链。
3. 因此"最简版本判据等于完整输入判据"在本轨迹族上是**可解释的结构性结论**，不是抽样波动。
4. 严格出生版本判据在间隔恒为 1 的轨迹上必然零晋升（已由两套独立计算验证）。

**不可以主张：**

- 不能说"两种策略在所有情况下等价"——只覆盖 append-only 单链、无空洞、使用前重校验这三个前提成立的轨迹族。
- 不能说"完整输入判据多余"——12 次起点反证上两条判据都拒绝，但本审计没有测"若移除使用前 EL 会多付出多少代价"。
- 不能把 69.017 s 读成端到端收益；它只是一个臂内的计算构成。
- 不能由"间隔恒为 1"推出"版本方法永远够用"；一旦出现回滚、多分支重放或跨会话共享祖先，前提即被破坏。

## 7. 对下一步的直接含义

要出现分歧，必须构造一个**规范链有空洞**的工作负载，而不是更多同分布的重复：

1. **被弃用的 frontier 不补算**（或补算延迟到隔代），使某次在飞调用的父状态跨两代；
2. **不兼容更新导致某前沿重算**，形成一次状态回退；
3. **多会话共享祖先**，使一个会话的 install 改变另一个会话的祖先有效性。

若在这三类负载上仍观察不到分歧，就可以有把握地写下"该判据在本文合同下不可替代性为零"这一负结论；若观察到，则分歧率、涉及计算量与期限信用差都可按本审计同样的口径直接报告。
