# RevTrace 跨版本有效计算的资源与时效账本（v1）

**2026-11-11。纯 CPU 只读重算，不产生任何新 GPU 或服务结果。**

数据源：`experiments/dsn_streamcorrect_independent_20261029/SERVICE_RESULTS_v1` 的 16 个冻结 cell（旧四来源，守恒臂 8 格 + 投机臂 8 格，每源两次 fresh-process 重复）。
本报告不修改 v15、旧独立确认或任何既有冻结记录。

## 0. 这份账本做什么

原文已有的 `92` 次跨版本晋升是**调用计数**，不能直接换算成计算或时间收益。本次重算把每一个 job 的 worker 侧实际计算记录（`native_jobs.jsonl` 的 `record`）与三本账（`FULLSPEC_LEDGER.json` 的 promotions / discarded / abandoned）逐 `job_id` 绑定，得到可按资源与时效分开报告的量。

**关键比值**

- 保留/沉没 = **5.11 : 1**（69.017s 对 13.515s）
- 单次保留平均 **0.750s**，单次早期拦截平均 **0.524s**

**92 条晋升的执行证据（已验证，不是假设）**：

| 检查项 | 结果 |
|---|---|
| `native_model_evaluated` | 92/92 为 True |
| `stage_execution` | 92/92 为 `original_full_infer` |
| `model_seconds` > 0 | 92/92 |
| `model_seconds` 范围 | 0.4452 ~ 1.1940（中位 0.7242） |

也就是说：这 92 次不是「声明为在飞」或「离线放行」，而是**确实执行了完整神经前向并跨越父状态被采用**。

## 2. 时效账（反事实估计，须与假设一起引用）

92 次全部能配对到其实际父状态的安装时刻，合计 **23.779s** 完成延迟节省。

| 统计量 | 值 (s) |
|---|---:|
| 最小值 | 0.043 |
| 中位数 | 0.251 |
| 最大值 | 0.414 |
| 合计 | 23.779 |
| 负值条数 | 0 |

定义：`时效节省 = (父状态实际安装时刻 + 本 job 的 model_seconds) − 本 job 实际完成时刻`。
含义是「若某策略在父状态安装的瞬间杀掉该在飞调用并重派，完成时刻会推迟多少」。
**这是反事实估计，不是实测重跑**，不能替代闭环三臂比较。92/92 为正，本次没有出现反例。

## 4. 新发现：拒绝路径是二分的，且存在竞态

既有汇总只写了「24 次 known_invalid_C_skips 与 2 次 discarded_full_results」。绑定执行记录后可以看到这两类**成本性质完全不同**：

| 类别 | 条数 | 平均 worker 占用 | 纯神经阶段 | 机制 |
|---|---:|---:|---:|---|
| 早期拦截 | 24/26 | 0.524s | 0.000s | `actual_canonical_disagrees_with_complete_start` 在 ASR 前缀阶段即被判定 |
| 晚期丢弃 | 2/26 | 0.471s | 0.463s | 同一证明类型，但完整模型已跑完 |

两条晚期丢弃出自同一说话人、同一 job 位置（`BAC009S0908W0369`，两次重复的 `j000016`，`witness_frontier=88000`），说明它不是随机噪声，而是**可复现的取消竞态**：证明与取消之间存在时延窗口，2/26 的在飞调用在被杀之前已经跑完了完整推理。

这给出一条具体的成本改进线索：当前投机成本之所以便宜（沉没 13.51s 对应 24 次取消），是因为 92.3% 的拒绝发生在神经模型之前；剩下的 7.7% 付出了**一个完整调用的神经网络成本**却没有产出。若把该证明的下发提前到 C 阶段之前，这 2 条的成本可降到与早期拦截同级。该项属于实现层优化候选，需独立版本与配对复测，本报告不主张已修复。

## 6. 可以主张什么、不可以主张什么

**可以主张（有本次重算支撑）：**

1. 旧四来源冻结轨迹中，92 次被实际采用的模型调用跨越了出生版本，**全部 92 次都实际执行了完整神经前向**，共消耗 69.017 worker-seconds。
2. 策略的正确拒绝成本是 13.515 worker-seconds（26 次），且其中 92.3% 发生在神经模型执行之前。
3. 保留与沉没的资源比为 5.11:1；这不是「节省 67.6% 计算」，而是「换回的合法工作」与「付出的投机成本」两个独立量的对比。
4. 92 次全部有正的完成延迟节省，合计 23.779s（反事实估计）。
5. 拒绝路径存在可复现的取消竞态（2/26 跑完模型才被丢弃）。

**不可以主张：**

- 不能说「版本策略会损失 67.6% 计算」或「节省 67.6% GPU 时间」——67.6% 是调用计数占比，不是时间或能量占比。
- 不能把 69.017s 说成端到端加速；它只是一个臂内的计算构成。
- 不能把本账本当作闭环三臂比较的替代：版本严格策略在真实重跑时还会改变调度、资源释放与重算时机，净效果必须实测。
- 不能把 `spec_total_wall_s` 与 `cons_total_wall_s` 之差解释为「投机开销 x%」——
  两者分别是 92.103s / 87.194s，覆盖的 job 数与调度不同（投机臂 162 次派发含 26 次被拒，守恒臂 136 次），差值混入了重复间方差，只能作描述性参考。
- 不能把单次 0.72s 的 model_seconds 直接外推到长音频工作负载；本数据是 500ms 前沿粒度下的短音频切片。

## 7. 对三项计划实验的直接输入

1. **R1 的定量前置已就绪**：三臂比较不再只是「92 次 vs 0 次」的计数叙事，而是有明确的资源构成（69.017s 换回 / 13.515s 沉没）。GPU 实验要做的是把这个构成转成同一合同下的端到端服务与能量差。
2. **ready_only 臂的预期差**：历史 `completed_full_buffer_reuse = 0`，意味着 ready-only 在旧轨迹里几乎退化为守恒臂；它的真实价值只能由闭环新跑测出。这与计划中的四臂设计一致。
3. **故障实验的可比对象**：本账本给出无故障条件下的单次调用成本 baseline（保留 0.750s、早期拦截 0.524s、晚期丢弃 0.471s），可作为 Owner-after-durable 分阶段计时的同源参照。

## 8. 口径与假设（引用本报告时必须同时给出）

- A1 计算成本=record.worker_job_wall_seconds；model_seconds 单列为纯神经阶段
- A2 跨版本=birth_canonical_sha != actual_parent_sha；相等的同版本晋升不计入
- A3 时效节省=(父状态安装时刻+本job model_seconds)-本job完成时刻（反事实估计）
- A4 被取消成本=worker_job_end_perf-worker_job_begin_perf（已实际沉没）
- A5 不混用 audio-s/GPU-s/J，不折算加速比
