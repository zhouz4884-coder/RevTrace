## 退出到实际服务：严格同输入的链条

K0/K1 内共找到 1,272 个唯一声明输入对，1,269 对完整输出相同；其中真正具有相同完整 processed tensor、实际执行 prompt/audio、peer 顺序的有 **675 对，675/675 完整输出相同**。同步为 600 对，错峰为 75 对。另三个输出不同的声明输入对，其完整 processed inputs 和 peers 均不同，不能称为同批数值不复现。

这里额外核实了 actual audit 字段确实存在，不能用两个缺失字典相等冒充同输入。6,357/6,357 个完整 worker 记录和 91/91 个取消行均有实际 tensor 的 shape/dtype/SHA 与执行 prompt/audio 证据；完整及取消行分别核实了 176/11 次已实际发出的 F2 target/donor 身份。原 fixture bytes、运行副本 bytes 和完整 JSON 对象分别绑定，实际 config 的完整 fixture 对象相同。这是 observer 输入证据，不是可信硬件执行证明。

同步每个 K1 run 恰好取消一条 covered 行。其下一批 16 行在 K0/K1 间 **16/16 输入、完整输出、实际 tensors 和 peer 顺序相同**；K1 的 16 行均被实际 Consumer 以完整原文应用，且均是 Consumer 首次达到该 targetF，确实推进了可见前沿。R1 下三次下一批的模型开始分别早 0.473/0.577/0.498 秒。取消请求、安全点 ACK、实际 batch drain 和下一次 dispatch 是不同事件，没有把 request 当成释放。

## 正常合法计算压力的尺度

逐行从完整实际 prompt、早于 enqueue 已发布的完整祖先链与同 F 的所选反馈状态重算，358 个实际 decode 跨 Canonical 且 targetF 尚未覆盖的事件中，242 个兼容、116 个不兼容、0 个未知。242 个兼容行均由实际 Consumer 完整应用；每格的合法数和原文身份在 `detail/LEGAL_PRESSURE_CONSUMER.json`。

R1/K1 的兼容正常计算见证数，sync 为 9/10/11，staggered 为 15/18/15；分别有 8/9/10 和 9/11/8 行本次实际完整显示同时满足 D2 与对应 C8。两种类型的工作在同一服务运行中确实并存：应保留的正常兼容计算，以及已被可信前沿覆盖的无用工作。

这仍不是长序列负载证明：这些正常兼容行最多生成 17 个新 token，最长实际 model-start→row-terminal 为 1.2919 秒。没有用错误 donor、sleep 或强制重复文本制造合法长计算，也不能据此声称固定 2 秒 watchdog 会误杀正常长输出。R0 也有合法在途行完成并被消费，故不能把所有跨 Canonical 在途见证都直接算成 R 因子的额外收益。
