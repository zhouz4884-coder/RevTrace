# CK5：1–5 步结项与研究判断

实验 ID：REVTRACE-CK5-20261026。正文、摘要、标题、参考文献均未修改。

## 结论

**本轮是正面的协议与恢复补强，不是新的独占调度算法胜出。** 已完成完整恢复路径、组合状态机、实际效果门控、Qwen/Whisper 同核实例及独立复算。84 个正式真实双 RTX3090 服务单元及最终源码下 6 个开发探针完成，各阶段独立事件审计和资产审计均通过。未在这些记录中发现未授权准入、Stale-as-Fresh、根不兼容实际视图或已确认输入丢失。

可推进的贡献是：在明确可信边界和适配器条件下，把认证状态、持久事实、实际视图、输入义务、冻结任务及物理 lease 放进一个执行协议，验证其组合交错；两个真实反馈表示共用此决策内核；恢复旧认证事实不再被下一次神经执行就绪挡住。**不能据此宣称新通用原语、完整 Standard 无法实现、独占加速、全栈机检或保证录用。**

## 恢复：最清楚的正面结果

下表为 fault 阶段三次重复中位数，单位秒。旧事实 RTO 是故障至**原持久前沿被实际本地 Consumer 重新应用**；新事实 RTO 是故障至首次新增认证消费。两者均包含整个进程组冷启动，原到达时钟不重置。

| 模型/方法 | 旧事实 legacy | 旧事实 early/no-kernel | 旧事实 early/kernel | 首次新事实 early/kernel |
|---|---:|---:|---:|---:|
| Qwen / DGFT | 31.013 | 14.494 | 14.736 | 33.829 |
| Qwen / 完整 Standard | 31.223 | 14.572 | 14.471 | 32.495 |
| Whisper / DGFT | 14.892 | 6.202 | 6.240 | 15.811 |
| Whisper / 完整 Standard | 14.726 | 6.228 | 6.241 | 15.493 |

早恢复组的全部 24 次 fault 运行，旧事实实际应用均早于两个执行器就绪。post-sync 的 8 次正式恢复也满足此关系；两模型旧事实约 14.45–14.57s / 6.13–6.21s，新事实约 32.40–32.58s / 15.33–15.35s。post-sync 没有运行 legacy 对照，不把它解释成该故障点的前后加速。

**实际价值**：可信旧事实的可用性不应等待未来推理资源；输入债务仍保留，不得因为恢复了旧文本就声称新音频完成。**负面边界**：冷模型加载仍主导新认证服务；36 次 fault 和 8 次 post-sync 全程双 SLO 均未通过。没有将旧 B 的 0.615s、小账本毫秒时间或 warm-worker 结果移植为本轮完整服务 RTO。

`RECOVERY_CLOCKS_v2` 另外分别保留故障前已接收债务清空、整个后续 offered 输入最终认证消费。前者若无债务是 N/A，不伪造 0；早期辅助字段 `kill_to_all_accepted_debt_drain_seconds` 实为最终 offered 消费，已明确被此复算替代。

## 正常服务成本与质量

normal 的 24 次全部满足测过的双 P99 目标，输入全部最终认证。内核开启相对于同方法 early/no-kernel 的 8 个同输入配对：Goodput 变化 **−0.130% 至 −0.418%**，GPU J/audio-s **−0.177% 至 +1.243%**；Display P99 增加约 **0.041–0.404s**，Commit-view P99 变化约 **−0.007 至 +0.292s**。这不是吞吐加速，也不声称延迟无成本或差异统计显著。

normal Qwen WER 为 4/199=2.010%，Whisper 为 29/199=14.573%；fault 为 9/402=2.239%、46/402=11.443%。这些值在各自模型、阶段、执行配置的三臂内一致；44 个预声明规范化历史比较组的 Z/P/text/frontier 历史都相等。边界 fine 运行的 Whisper 质量较差，不能用不同声学分段跨阶段推导质量改善。无跨模型 WER 优劣或 SOTA 主张。

原 DGFT 和 Standard 继承限流策略定义仍有差异；normal/fault 实测最大 reserved debt≤85.745s，低于 Standard 的 96s，故共同 96s 上限在这些轨迹上不绑定。收益主要采用**同方法三臂**归因，不宣称跨方法限流本质等价或独占性能。

## 迟到 Private：合法进展与 Fail-closed 同时成立

在真实 A6 完成后暂缓安装，等真实 P8 完成，再先安装 A6、后交付同一 P8。16 个正式服务运行产生 64 个源/条件/重复的观测：**56 次兼容链保留实际 8s Provisional 前沿，8 次不兼容链撤回到 6s 认证前沿**，均没有拼接认证后缀或授予虚假新覆盖。两模型、完整 Standard 与 fine 正控制共用相同保护。

一条合成 coherent P6 载荷只改 SID0 的低信任结果；其本身不是新神经生成。随后 P8 是真实模型消费与完整输出，其实际反馈输入经资产重放检查。整个阶段是受控交错可达性，不是自然频率。兼容保留说明不必 reject-all；不兼容撤回说明显示权限没有升级为 Canonical 写权限。该证据属于已有因果协调的完整组合验证，不是新 C2 调度胜利。

## 形式化、回归与真实执行对应

- Linux 和 Windows 均为支持范围 258 项回归 + 12 项外部协议控制通过。不是所有历史仓库脚本均可收集；旧冻结包缺少无关脚本导致的 19 个 broad-collection 错误保留。
- 单会话有限乘积：1,154 状态、3,429 边、216 非法事件被拒、40 合法进展状态；两个 Worker、一次重启、一个认证区间和一个超前 Private 区间等明确界限。
- 双会话部分提交切片：308 状态、735 边、48 非法事件被拒、6 完整进展状态；72 个状态允许共享物理 Batch 尚未 drain 时其中一会话已合法安装。
- 两套 Linux/Windows BFS/DFS 精确状态集哈希一致。两套模型不能相加包装成无界完整服务证明。
- 三个规则删除执行反例和四组信息不足对照。结论是给定观察模型下的充分条件/区分信息需要，不是所有实现必须采用同一 guard。

可信选择/渲染、单 Owner、不可变音频、完好持久存储、实际 Consumer 收据和进程组死亡围栏为假设。没有证明硬件/宿主 Byzantine 安全、断电行为、远端浏览器网络 RTO、无限活性或完整 Python/CUDA/OS refinement。内核保留全历史并在 step 深拷贝，本轮短窗口成本不代表长期内存有界。

## 保留的失败与修正

1. 初始 Whisper convenience API 去掉 EOS，严格结果接口失败。保留 ck5_v1 原始失败；改用底层完整序列、实际 decoder 前缀和 EOS。16 次真实 GPU same-input/repeated native-text oracle 通过后才运行正式矩阵。
2. 第一版 CPU asset checker 同时选中同窗口 P/A，修正为明确 proposal；不重跑 GPU，原 STOP 保留。
3. fault 的一个 owner logical-enqueue 发生在 SIGKILL 前、Worker pre-submit 前，不能当缺失 GPU 结果。独立检查器区分 owner enqueue / 物理提交 / 完整结果，原36条运行不重跑，所有实际消费/提交仍必须有真实对应行。
4. 外部 CPU abort 测试原本要求从未接收的 offered 会话也完成，与原超时拒绝规则矛盾；native same-input oracle 相同。修正测试前提，不修改准入/超时策略。
5. 最终恢复时钟复算脚本的一处多余括号导致 CPU 后处理停止。保留原脚本失败日志，版本化语法修正后复算；无 GPU 重跑、无数值手改。
