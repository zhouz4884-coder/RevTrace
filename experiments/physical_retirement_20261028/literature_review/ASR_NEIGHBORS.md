# Streaming ASR and revision neighbors

Verified 2026-10-28. This is a bounded primary-source literature/code review, not an experiment or a native reproduction. It supplements `COMPARISON.md` and `BASELINE_IDENTITIES.md`; it does not re-review their serving/distributed-systems neighbors.

**Assessment:** there is a credible application/composition opportunity. Streaming ASR already has stable-prefix selection, decoder-state reuse, correction feedback, output replacement, context retention, and early decoding stops. The useful RevTrace question is more specific: under the same complete trusted feedback history, can independently advancing authoritative state coexist with preserved compatible private computation and useful visible progress, while obsolete computation actually stops? Established ingredients do not make this combination valueless. Its value must be established by the behavior and interaction it enables.

Academic-search MCP tools were absent from the available catalog. The required `nature-academic-search` manifest, core modules, and multi-source workflow were read; discovery used web search and verification used ACL Anthology, ISCA, arXiv, and pinned author repositories through the GitHub connector. For simulstream, the web tool could not fetch the publisher PDF, so arXiv v3 supplied full text. **StreamCorrect was subsequently obtained directly from the official ACL OA PDF using the local network**, following `nature-downloader`; its 13 pages were verified and its relevant methods/evaluation sections read. Initial web-tool failure was not an access-rights failure. See the [acquisition manifest](streamcorrect_fulltext/MANIFEST.json) and [full-text review](streamcorrect_fulltext/READING.md). The paper explicitly links the reviewed author repository; exact equivalence between a public commit and the paper's executed implementation is not established. No absence-of-prior-art claim follows from this search.

## What is actually coordinated

Here, “authoritative” means each neighbor's own output rule, not a claim that it satisfies RevTrace's full Canonical contract. “Not specified” means outside the mechanism established by the cited sections/code, not impossible to add.

## StreamCorrect: the closest feedback neighbor in this search

The **full paper** specifies a selected-feedback loop: ASR generates top-k candidates from observed audio and the prior confirmed prefix; the learned corrector chooses the current segment, which is appended to that prefix before the next chunk (Fig. 1, §3.1 and §3.2, pp. 2393–2395). PRA recovers training-supervision boundaries from reference transcripts; its deterministic alignment tie-break is not a runtime certificate of neural state or transcript correctness. This is concrete correction-to-feedback coordination, not merely a surface similarity in model names. [Paper](https://aclanthology.org/2026.emnlp-industry.142.pdf).

The paper also describes a real industrial integration: complete ASR+corrector replicas per worker, call-level process parallelism, and an 8-new-token cap per 500ms correction step (§4.5, p. 2397). That cap bounds work before execution; it is distinct from terminating an in-flight target after another trusted result makes it obsolete. Its positive accuracy/latency results and their experimental scope are recorded in the [full-text review](streamcorrect_fulltext/READING.md).

Public author code adds implementation detail:

- **Whisper implementation, commit `bbb9f7fde13fabb6c0940f5bae215150d1ea1cb3`:** `infer()` chooses the corrector's appended token IDs when available, appends those tokens to the next prefix, clears caches, and returns the corrected hypothesis. This is concrete correction-to-feedback/context coordination; it must be credited. [Exact path, lines 1095–1138](https://github.com/vu-duy-tung/StreamCorrect/blob/bbb9f7fde13fabb6c0940f5bae215150d1ea1cb3/simul_whisper/simul_whisper.py#L1095-L1138).
- **Separate Qwen3-ASR repository, commit `cdd874ea318da7629d1af523794fcf8d6a8db5ec`:** despite the `_async.py` filename, the reviewed `_beam_search()` issues a blocking `model.generate()` per block and performs beam expansion afterward. `process_iter()` calls ASR, then the corrector, and returns latency information; `finish()` constructs the output transcript. Parallel batch workers process different files. Do not equate this label with overlapping old/new feedback-root inference. [Block call](https://github.com/vu-duy-tung/StreamCorrect_Qwen3ASR/blob/cdd874ea318da7629d1af523794fcf8d6a8db5ec/qwen3asr_streaming_vllm_beam_async.py#L287-L330), [iteration](https://github.com/vu-duy-tung/StreamCorrect_Qwen3ASR/blob/cdd874ea318da7629d1af523794fcf8d6a8db5ec/qwen3asr_streaming_vllm_beam_async.py#L487-L559), [final output](https://github.com/vu-duy-tung/StreamCorrect_Qwen3ASR/blob/cdd874ea318da7629d1af523794fcf8d6a8db5ec/qwen3asr_streaming_vllm_beam_async.py#L561-L660), [batch driver](https://github.com/vu-duy-tung/StreamCorrect_Qwen3ASR/blob/cdd874ea318da7629d1af523794fcf8d6a8db5ec/streaming/asr_runner.py#L119-L196).

The distinction is now grounded in the paper's **explicit sequential chunk contract**, not only code searches. Its state is the corrected confirmed prefix, rather than an independently advancing trusted history plus retained private branches and their exposed view. The paper does not define that cross-root compatibility contract, accepted-input/WAL recovery, or worker-acknowledged retirement/lease reclamation. Its evaluation does not establish these properties. This is a scope distinction, not a claim that StreamCorrect cannot be extended. Its chosen correction can itself serve as the fixed trusted decision stream in a controlled adaptation, with RevTrace responsible for preserving that exact stream while changing concurrency, Consumer handling, and execution lifetime.

## Competitive opportunity and decisive experiment

The difficult composition is an **asymmetric progression problem**: authoritative progress can invalidate one private request while leaving another useful. A root change is neither permission to publish every late result nor a proof that every old-root computation is useless. A consumer also needs to preserve useful visible output when compatibility permits it, and withdraw incompatible output when required. This is the proposed application-specific systems contribution, not a demand that each primitive be new.

The strongest evidence would establish the following on the same inputs, offered load, resources, full Canonical F/Z/P/text history, and accepted-input obligations:

1. **Compatible continuation:** a trusted-root advance occurs while a private branch remains useful. Its work survives and produces actual Consumer-visible progress. Compare retain/drop × one-lane/two-lane, and a complete author-built Standard receiving the same capabilities. Show the interaction, not just two isolated wins.
2. **Required withdrawal and late arrival:** another advance makes a previously exposed branch incompatible. Demonstrate the necessary withdrawal and rejection of late output while trusted history stays unchanged. Report rollback extent and duration, rather than promising zero rollback.
3. **Obsolete execution:** actual installed trusted coverage proves that an in-flight target is already covered. Trace cancellation request → worker safe-point acknowledgement → terminal row → synchronized batch drain → next legal work. Compare row-complete, strong watchdog, parent cancellation, and trusted coverage with the same actuator. A heuristic can perform equally well on this trace; retain that result.
4. **Input/recovery obligation:** accepted audio remains accounted for through a relevant worker interruption/restart if fault tolerance is claimed. A displayed transcript alone cannot establish this property. Natural prevalence, controlled revision schedules, and deterministic obligations should remain separate evidence tiers.

The most discriminating missing observation is **real compatible private progress surviving an actual trusted-root advance, alongside required incompatible withdrawal, under unchanged trusted history**. It separates this problem from simply waiting for stable ASR, running a corrector sequentially, or cancelling every old parent. Physical retirement is complementary: fewer generated tokens matter only when legal work actually starts or progresses earlier.

If full Standard has the same effect, it is a successful constructive alternative and a sufficiency result for the composition. It is not external prior art and does not erase the author's combination. The paper can then contribute the contract, coordination design, interaction evidence, and service characterization without claiming an exclusive policy advantage.

## Claim boundary after the current experiments

This review generated no runtime measurements. The parent experiment team reports that trusted coverage exercised real decode exit, while strong watchdog/parent policies were also effective and additional causal-generation predicates were not exercised. These outcomes must be linked to that experiment's own frozen manifest and raw results before paper use.

A defensible candidate sentence is: “RevTrace coordinates speculative computation and consumer-visible revisions around an unchanged trusted feedback service, retaining compatible progress across trusted updates and retiring work once installed trusted coverage makes it obsolete.” Attach measured outcomes and workload scope after validation.

Avoid first stable prefix, first reusable decoder state, first correction feedback, first revisable streaming display, first early ASR decoding stop, or superiority over all cancellation mechanisms. Do not attribute a coverage-only result to unexercised causal predicates. Full Canonical-history preservation, useful visible progress, accepted-input recovery, and physical resource release are separate claims and require their own evidence.
