## Lifecycle and invariants

CancelRequest registers an immutable full job/worker/batch identity before IPC.
A request does not complete a row or release a Worker. RowCancelled is a distinct
decode-safe terminal containing identity, count and clocks, with no selected
tokens, text, Phi or state result. RowComplete remains a full declared EOS/budget
selection with trusted rendering. These terminals are disjoint. BatchDrained
requires exactly one terminal per issued row and actual synchronized physical
completion before worker reuse. Completion can win a cancellation race.

The first actuator preserves fixed peer layout. Cancelled rows are masked until
the whole generation returns; their residual masked-row computation stays fully
charged. Only measured earlier generation return + CUDA synchronize + actual
BatchDrained supports physical resource reclamation. No per-row FLOP reclamation,
CUDA-kernel preemption or continuous-refill claim is made by this prototype.

No cancelled prefix can publish as a complete provisional result or install
Canonical state. All selected generation, D1, parent/frontier/contract checks,
WAL, actual local Consumer, original input clocks and accepted obligations remain
active. No Authority row is cancelled. Every offered interval remains measured.

## Shared-actuator controls

- original row_complete: physical exit disabled, original complete-row path;
- no_cancel: actuator enabled, no requests, same-input/numerical no-op control;
- watchdog: frozen timeout since actual worker start;
- parent: conservatively cancel on parent-version supersession;
- covered: cancel when current trusted Canonical covers the target;
- causal: covered or an explicitly retired Private generation, preserving old
  parent work that can still be legally useful.

Causal and covered may behave identically; record that result. Parent cancellation
is not the full Retire system. Retire is a direct execution-version/physical-exit
neighbor and can accept runtime-defined supersession. Compare its scope accurately.
Full Standard given our complete composition is an alternative implementation
positive control, not external evidence that the composition predates this work.

## Source and run records

Every execution uses a clean separately committed checkout and complete byte
manifest; full source history resolves locally and on the experiment disk.
The local no-argument identity preflight is updated only to a new frozen pointer,
never to relabel historical results. Before launch record experiment ID, source
commit, config/environment hashes,8TB raw path and intended summary/gate paths.
All model/data/cache/environment/raw logs remain on the designated8TB disk.

On failure retain exact inputs, attempted source, logs and failed gate; diagnose
same-input repetition, legal reference and model/numerical controls before repair.
Changes get a new commit/source manifest and fresh output directory. No hidden
reruns, silent source overwrite, forced empty completions or threshold chasing.

## Decision evidence

Operator: repeated complete/cancel manifests; actual model interval and drain;
surviving row output/Stop/input equivalence; all costs. Serving: all offered
frontiers, actual Consumer clocks, other-session stalls, sustained legal progress,
certified coverage/quality, accepted debt, full physical occupancy and energy.
The release effect must be distinct from model-loading/startup or a changed
Canonical task. Formal/recovery work is limited to the new lifecycle obligations.

Completion requires implementation, necessary real probes/controls and repairs,
actual service gate, independent composition confirmation, baseline identities,
negative boundaries and a result-based assessment. A green CPU suite, archive,
operator speedup, source gate or plan alone does not complete this family.
