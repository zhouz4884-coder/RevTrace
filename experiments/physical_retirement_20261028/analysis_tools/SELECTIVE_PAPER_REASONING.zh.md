# RevTrace：选择性研究判断与论文收束

日期：2026-10-28。性质：研究综合与决策说明，不是新实验、代码审计、全文修改或录用预测。本说明完整阅读了用户提供的长建议，结合本目录文献核查、已有服务实验与 DSN 阅读笔记形成独立判断。本文不要求每条研究假设成功，也不把内部不同实现当作外部已有工作。

## 1. 我选择的中心问题

**在保持完整可信反馈历史不变的前提下，如何让可信状态独立推进，并保住仍然合法的临时计算与用户可见进展？**

更具体地说：可信服务独立确认新状态，Private 分支可能出生于旧 root 却仍然有效；已经合法显示的 Private 进展也可能仍然有效。反过来，有些旧结果确实不兼容或已被覆盖，必须撤销或停止。问题是如何让计算与实际 Consumer 对这几个情况做出一致、足够细的决定。

这个问题比“反馈式生成服务中的合法进展保留与故障隔离”更窄，适合作为论文的主问句。故障隔离是要测出的结果之一，不能先把广泛隔离能力当作已有结论。也不应把每项历史机制都升级为一个并列贡献。

**候选论文主张：** RevTrace 在独立可信反馈与临时计算之间建立显式兼容关系，将计算继续与 Consumer 可见进展的保留共同约束于该关系；在被可信覆盖证明已无用途时，再通过真实执行退出恢复其他合法工作的及时执行机会。完整 H3 支持 Qwen 错峰工作点的条件性交互，尚不支持跨模型、跨到达的一致优势。

## 2. 哪些内容够成贡献，哪些只是必要支撑

| 层次 | 我建议保留的内容 | 科学问题与证据义务 |
|---|---|---|
| 贡献一：应用中的协调缺口 | “旧版本”不等于“无用”，“保留计算”不等于“保留用户进展” | 用真实交错说明普通版本围栏和显示替换分别丢掉什么；不能仅提出新术语。 |
| 贡献二：具体组合机制 | 在指定音频边界上核查实际反馈状态投影，沿实际依赖链连接 Private 结果；计算保留与 Consumer 共同遵循关系 | 给出假设、充分条件及保守拒绝规则。实际 worker 输入、完整输出和已发布依赖是证据；字符串相似、版本号及部分输出不是。 |
| 贡献三：能力与代价的实证 | 同完整可信历史下的合法连续进展、必要撤销、质量/成本以及故障传播边界 | 严格 2×2、独立来源、完整 Standard 正控、物理退出服务案例各有自己的角色；不能把所有结果相乘。 |
| 执行支撑 | 认证逐行交付、可信覆盖触发的安全点退出、物理 lease 账本 | 解释如何把合法结果实际送达与把执行器实际释放区分开。当前不能独立宣传为新的通用组批或取消算法。 |
| 次要扩展 | 既有可信事实的恢复、WAL/输入义务 | 可支撑故障语义。当前 light renderer 单次对照和未全面改善的指标不足以另立恢复性能主贡献；篇幅不够时放附录或后续工作。 |

这里不把“保留与退休共享同一判据”写成已经证明。兼容关系证明某分支仍可用；安装后的可信覆盖证明某任务没有剩余用途，两者不是同一个命题。目前真实 causal 臂仅触发 `trusted-coverage`，不能把未触发的 `retired-generation` 归因到实测收益。

## 3. 我对用户长建议的取舍

| 建议 | 决策 | 原因及落地方式 |
|---|---|---|
| 完整 Standard 同效不能反证原创 | **采纳** | 它获得完整方法后是替代实现正控。保留它，明确继承了哪些组合能力；外部原生/忠实适配、部分消融、完整正控分表说明身份。 |
| 研究内部早期机制仍能计入整篇贡献 | **采纳** | 评价整套方法相对外部工作的增量，不仅评价最后一轮提交。历史数字仍须绑定各自源与合同。 |
| 旧 2×2 是中心机制线索 | **采纳并限制** | 计算保留单开增加回撤、联合开启减少回撤，是有内容的冲突线索。但旧 snapshot 不等于当前严格 checked_snapshot；旧三次时序重复不能冒充独立来源确认。 |
| 把四个边界全部组成主线 | **改写** | 计算与可见进展是中心；行完成/物理释放是执行支撑；可信事实恢复是扩展。四条平铺会弱化问句，且恢复证据目前较少。 |
| 物理退出成为最强新增支点 | **按实测收束** | 已见真实服务收益，值得保留；watchdog/parent 同样有效，完整 causal 未表现独占优势。因此写成合法工作赶上有用窗口的能力，不写取消策略全面优胜。 |
| 补进展撤回与被额外阻塞的时间 | **采纳** | 用实际 Consumer 和全 offered 分母解释原 D2/C8；它们不能取代原 SLO，也不能把后见 Canonical 一致称作在线正确认证。 |
| 正常、迟到交付、解码长尾、进程崩溃全部统一重跑 | **暂不作为默认任务** | 先读完整 H3 与已有各类证据。如果统一源上仍有明确未覆盖性质，只做能改变核心判断的最小干预；不因“四种条件齐全”另开全矩阵。 |
| 为所有失败分支继续找修复 | **不采纳** | 复杂 CES、独占 causal 优势、自然大尾部普遍性不必成功。失败定位后可冻结边界，保留中心组合已有的正、负证据。 |

附件中 T1/T3、旧 2×2、逐行交付和 renderer 数字用于识别候选论证位置；本说明没有重新重放这些历史原始文件，因此不将它们列为本轮新核验的测量结果。主文引用前应指向其原始有界证据，而非引用建议文本本身。

## 4. 对最近外部工作的可辩护区别

### StreamCorrect

完整正文的顺序合同是：ASR 候选 → corrector 选择 → 追加至 confirmed prefix → 条件化下一块。纠错到反馈的协调、实际工业整合及有益识别结果必须被明确承认。不能声称首次纠错反馈、首次保存上下文或首次流式修订。

RevTrace 可争取的区别是：**可信选择继续独立推进时，多个 Private 分支以及实际 Consumer 如何跨 root 保持合法联系。** StreamCorrect 被核查的正文没有给出这一跨 root 关系、旧异步结果的消费授权，以及 worker 确认的退休/lease 回收合同。这是问题范围区别，不是声称其不可扩展，也不是新方法一定优于其原任务。

最公平的应用检验是把相同完整纠错选择作为可信流，比较同输入义务和资源下的保守顺序方案、严格因子臂及完整组合。若尚未在 StreamCorrect 原环境完成，论文应写“受其反馈合同启发/适配”，不写原生复现或识别性能胜出。现有 H3 的原可信服务确认不能自动叫作 StreamCorrect 实验。

依据：[ASR 邻居核查](../literature_review/ASR_NEIGHBORS.md)、[StreamCorrect 全文阅读](../literature_review/streamcorrect_fulltext/READING.md)。

### Retire

Retire 已明确研究版本 authority、`SUPERSEDE`、有界旧执行、有效前缀继承和异步资源回收。不能用“保留＋取消”这几个词声明原创，不能把保守 parent_cancel 臂的表现叫作完整 Retire 的胜负。

可争取的应用增量是：**反馈场景如何推导该继续与该退休的范围，并把这个范围同时落实到生成链和可见服务。** 一次可信 root 更新并非对所有旧 Private 的统一 supersession；同边界实际状态与依赖可以证明部分旧工作继续有效。Retire 可以由客户提供这样的范围；RevTrace 需要证明这层语义集成确实必要且有用，而非声称通用执行底座缺少取消。

如果 watchdog 在本压力样例同样救回服务，那是结果；如果简单 coverage 足够，就采用简单解释。只有实际出现“版本变了但兼容分支有用”并保住服务时，才增加反馈语义相对统一父版本取消的依据。

依据：[机制比较](../literature_review/COMPARISON.md)、[基线身份](../literature_review/BASELINE_IDENTITIES.md)。文献检索是有界核查，不构成“没有任何先例”的穷尽证明。

## 5. 当前已经比较扎实的正结果与它的边界

物理退出正式 16/16 cell 已完成并通过独立审计；所有来源的完整 Canonical `F/Z/P/text` 一致，输入义务清空，最终 WER 为 14/687。相对 row-complete，covered 的两次双期限信用分别净增 **15.385 / 17.255 秒**，分母每次为 **250.18 秒 offered 音频**。后见同 F 全文一致的支持信用重计后，净增仍保留。

最有解释力的控制不是模型阶段减少多少，而是：后继批次 **16 行的实际输入、完整输出及 peer 顺序相同**，原臂全部成为 obsolete，及时释放执行器后全部实际显示。这证明真实资源生存期影响了相同合法工作的服务价值；不是删日志或改期限的收益。

同时保留以下事实：整场总模型阶段没有降低；所有 16 个 cell 均未通过整场 D2/C8 双 P99；r0 有 4.755 秒原通过信用丢失，个别其他会话停顿变差；watchdog 与 parent 也获益；同一个旧开发来源与两个重复不支持自然异常普遍性。后见同 F 支持不是 ground-truth 正确率，音频前沿不回撤也不是文本零修订。

因此物理退出目前足够作为**服务时效的机制案例与有边界的执行增量**，不足以单独承担“通用故障隔离框架”或“总体 GPU 降本”主张。

依据：[正式强对照](PILOT_v2_FINDINGS.zh.md)、[同输入输出服务链](../service_opportunity_v2/REPORT.zh.md)、[后见同 F 支持重计](real_service_full_v2_usefulness_v1/FINDINGS.zh.md)。

## 6. 完整 H3 之后，我选择什么

正式聚合已经完成：**110/110 格接受独立审计，22 个完整 2×2 区块，24 个新 speaker、714.11 秒不重复基础音频**。全 144 个更宽的 source/runtime/arrival 历史组都保持完整 Canonical F/Z/P/text 相同，缺失历史为零。110 格、多个模型、重复及大量窗口均不增加独立 speaker 数。此次读取的是既有 GPU raw 的正式聚合，没有新增推理。

**最适合主打的是 Qwen、rho1、错峰到达的条件性交互。** 下表对三个预先冻结的 cohort 各执行一次，分母每臂都是全部 **714.11 秒**，不是只挑可兼容事件。支持信用定义为“首次即认证 + 首次提前且后来同 F Canonical 全文一致”，不是仅 ahead 单项。本层原文与规范化支持相同。

| 严格臂 | 总双期限支持信用，秒 | 音频前沿回撤，次 / 秒 | compatible 机会 / 全部实际 Consumer 更新 |
|---|---:|---:|---:|
| R0_S0 保守基线 | 654.115 | 12 / 10.505 | 6 / 368，均被清除 |
| R0_S1 仅 Consumer | 628.435 | 1 / 0.560 | 4 / 368，均被保留 |
| R1_S0 仅计算保留 | 664.150 | 17 / 18.570 | 17 / 368，均被清除 |
| R1_S1 联合 | **680.760** | **0 / 0** | 18 / 368，均被保留 |
| STANDARD_FULL 正控 | 667.530 | 0 / 0 | 15 / 368，均被保留 |

联合相对基线多 **26.645 秒，即 3.73 个百分点**；相对仅 Consumer 多 52.325 秒，相对仅保留多 16.610 秒。三 cohort 的基线→联合信用分别增加 **3.615、13.650、9.380 秒**，没有只靠一个 cohort 得到总正值。但机会本身受 arm 改变，不能把 18 对 6 当成同一批潜在机会的成功率对照。逐 speaker 的基线→联合仍有 11 个改善、10 个持平、3 个变差，不能声称人人受益。

这保留了附件最有价值的解释：计算单开得到更多及时工作，却发生更多回撤；Consumer 单开少回撤，却损失及时性；联合解除这个特定冲突。它是当前严格 checked_snapshot 与新来源上的观察，不需要借用旧 snapshot 的大效果。

因子交互聚合为 680.760−664.150−628.435+654.115=**42.290 秒**；三个 cohort 的交互各为 +18.530、+6.205、+17.555 秒。按 speaker 聚类的描述性 bootstrap，双期限占比交互均值 **+5.90 个百分点，95% 区间约 +1.13 至 +10.28 个百分点**。这是**交互估计**，不是联合对基线的区间；speaker 共享 cohort 服务，不能当成 24 个独立 GPU 部署。它支持有限的组合互补解释，不支持普遍优势。

同样重要的边界是：

- Qwen 同步主层机会稀少，联合只有 **3/368** 个可兼容显示保留机会；信用 708.465→711.440 秒，接近天花板，R1_S0 反而有 712.230 秒。因此不声称所有到达方式都有相同组合优势。
- Qwen 错峰五臂全部没有通过整场双 P99。联合的实际 display P99 在三个 cohort 都低于基线，但连续进展最大停顿不是相对每个消融都更好；不能写全面消除停顿或已达到部署 SLO。
- Qwen 主层所有臂最终 micro-WER 都是 **26/1908=1.3627%**。这是相同可信选择下的质量保持，不是新的识别算法收益。前沿零回撤仍不等于全文零修订。
- Whisper rho1 的所有臂保持相同但很差的最终质量：**micro-WER=1586/1908=83.1237%**；cohort 平均与 micro-WER 是不同统计量。它可作为适配/合法性与失败边界证据，不能当“第二模型上有实用服务价值”的正验证。
- rho3 的非共同边界不能充分与同 F Canonical 配对：联合 Qwen 有 **464 秒**及时 ahead 音频、Whisper 有 **422 秒**未匹配。较低最终 WER 不能把这些未匹配音频补成有同 F 支持的进展，也不能替代强交互证据。
- Full Standard 在 Qwen 同样保住了零前沿回撤；它不是外部已有系统。当前有界时序差不值得再制造“必须胜过完整正控”的研究目标。

因此我的最终选择是：**中心组合得到有条件的实证支持，最强证据集中在 Qwen 错峰工作点；双模型普遍优势与整场 SLO 通过不成立。** 全 110 格的总机会率仅描述本冻结设计，不能作为自然用户发生率；两套机会时钟也不能相加。同步、Whisper 和 coarse 的限制必须在结果中保留，不能从主矩阵删除。

依据：[完整聚合](../H3_RESULTS_v2/aggregate/SUMMARY.json)、[逐格结果](../H3_RESULTS_v2/aggregate/RUNS.json)、[交互与聚类区间](../H3_RESULTS_v2/aggregate/SPEAKER_BOOTSTRAP.json)、[后见支持](../H3_RESULTS_v2/usefulness/RUNS.json)、[机会分层](../H3_RESULTS_v2/opportunities/STRATIFIED_RATES.json)。

## 7. 当前不再追加 GPU；后续只做能改变核心判断的工作

**本轮已有 110 格确认与 16 格物理退出强对照，足够形成选择性研究结论。** 当前不为让同步、Whisper、coarse、复杂退休谓词都成功继续启动运行；也不把所有历史工作点重新交叉为一张大矩阵。先把已有真实结果组织成可核查的论证。

最有价值的非 GPU 工作是把核心关系与适用条件写清：同音频边界、实际反馈状态投影相同、每条 Private 边消费真实前驱完整输出、分支确实可达、在途任务冻结输入为合法后继。证明限于声明的模型/数值和运行假设。缺一项为何必须保守拒绝，可用可复算的最小 CPU 反例说明；不需要把普通 CAS/WAL 再包装成主定理。

如果下一阶段投稿前仍发现明确缺口，可按其信息价值只选一个：缺少兼容与不兼容的易懂因果实例，就从既有 trace 抽取最小时间线；若未来主张要扩展到真实 StreamCorrect 纠错服务，才值得接入真实固定选择流。当前 H3 已有实际兼容保留、严格因子效应和不兼容清除，不需要为了“每种交错都试一遍”预定新 GPU 任务。对未验证的外部系统仍保持能力范围比较，不写原生部署优胜。

新 CES、大规模异常提示扫描、为 renderer 重做整系统、所有退休原因强行触发、所有故障交叉所有 rho/到达/模型，都不进入当前必做清单。它们只有在具体缺口与端到端价值同时明确时才重新评估。

## 8. 最终写作选择

建议以“可信反馈推进中的合法临时进展保留”组织论文：一个真实冲突开场 → 明确契约与兼容关系 → 计算与 Consumer 的组合 → 严格因子与独立确认 → 真实资源退出案例及代价。逐行交付与输入义务在实现和故障语义中说明，恢复扩展按篇幅取舍。

这与 DSN 阅读样本展示的论证方式一致：构件已有不妨碍组合贡献，但必须说明新的服务缺口、为什么需要该组合，以及完整控制下增加了什么能力。录用样本没有拒稿对照，不能推出录用概率或共同技术配方。

当前的研究决定是：**保留并集中发展中心组合问题；以 Qwen 错峰的严格交互与真实执行时效案例支撑；接受同步低机会、Whisper 质量失败、全 run SLO 未通过以及独占取消优势未成立；本轮不追加 GPU。** 这是有边界的组合/应用型论文方案，尚不能由这些结果保证竞争力或录用。
