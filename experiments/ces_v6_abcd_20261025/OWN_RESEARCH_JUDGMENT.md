# 我的独立判断：真正的控制点，不是再加一个因果权重

本文件是结果解释和未来可证伪设计，不是新GPU成功结果，也不修改论文。

## 1. 本轮证据改变了什么

C证实了一个真实的非抢占代价放大路径：Authority5的**安装**晚于下一次
Private6输入冻结，导致Private6沿另一条实际反馈输入执行。三次配对中，
Private6由10 Token变成256 Token触顶，所在Batch约1.6s变成14.2s。
该Batch的Lease不是这一行独占成本；整个运行GPU0净增约5.84–6.29s。

关键时刻可写成：

    tau_next = max(audio_release, GPU0_batch_drained, private_dependency_ready)
    conditioning_input = Phi(canonical_new) if install_time <= tau_next
                         else Phi(current_private_branch)

它是带实际派发边界的分段关系，不是“每晚1秒就增加固定GPU成本”的线性律。
0.75s干预虽已跨过音频释放，却仍赶在关键Private派发前安装，所以未触顶。

## 2. 为什么不能照搬到GPU1的Verify/Generate评分

全部受干预的Authority5任务派发时都没有已返回候选。关键来源在正常运行中
候选2.60–2.71s才返回，而Fine已约1.70s返回。立即动作集合在这一时刻只有G；
风险评分不能凭空创造另一个可执行动作。付费等待可以改变集合，但也要真实
支付等待、验证和回退，不能用后来观察到的候选当作派发时已就绪。

D在新来源上的主要问题也不是相同触顶：独立36个运行的Private触顶为0。
全部98个运行的13个触顶仍只来自旧来源1993-147149-0020，其中10个不属于C
人工安装延迟组。不能把对这一条输入的修复当作跨来源算法成功。

## 3. 真正值得考虑的下一控制动作（尚未实现）

若以后在未见工作负载上确认存在足够多的可避免旧输入长尾，控制点应放在
**尚未派发的下一次Private生成**，而不只是GPU1切换证据类型：

* 原允许任务仍通过同一Parent/Frontier/Contract/D1；预测不产生写权限。
* 对即将跨过未认证区间的Private任务，比较立即执行和有限等待Canonical
  更新的真实代价。已经在GPU0运行的任务不得当作可回收成本。
* 如已有完整可信Authority结果但尚未安装，可只读检查其声明投影与Private
  状态的兼容性，用作成本决策信息，不能提前把它当Canonical Parent。
* 不兼容或尚无证据时，最多等待显式有限预算，随后重新检查实际状态。
  重新构造任务须用新身份与实际输入；不得复用旧Z冒充新Parent生成。
* 必须比较静态领先限制、纯时间等待、兼容性门控，以及相同能力的完整
  Standard/Fine控制。若普通有界背压已足够，就不能把复杂规则叫独立创新。

目标应是实际未来工作负担与双期限剩余信用，而不是Private后代数量：

    value(wait) = expected_audio_credit(wait) - expected_audio_credit(issue)
                  - opportunity_rate * extra_wall
                  - expected_paid_work_externality(wait vs issue)

所有量必须由决策时可观察信息预测；未知未来Token长度和注入标签不能进入。
安全由旧准入不变量闭包支撑，性能仍是待测命题。有限等待也不是SLO保证。

这个设计尚不满足本轮大规模实施门槛：当前独立来源没有复制该触顶，不能
为了得到好图专门筛选那个旧输入或只在人工hold下宣称普适收益。应先找真正
可迁移、可执行且有明显端到端空间的机会，再开展下一轮，而不是换算法名字。

## 4. B的NO-GO也必须精确定义

192个首次失配位置很早，说明本轮“复用很长的已验证**候选前缀**再续写”的
路径缺乏观察支持。这**不能证明**相同目标输入的prompt/audio前置计算复用
没有空间；两者是不同对象。后者尚未评估，必须先分解真实Encoder/Prefill/
Decode成本，再验证缓存来源、实际数值路径、完整Token/停止/投影及公平共享
基线。本轮没有提前实现新KV Fallback，也没有把未执行设计算成收益。

## 5. 对DSN贡献的含义

C可成为双时间线机制必要性和失效边界的新证据；A/B是有明确范围的工程与
数值研究；D决定的是这个具体Fine-anchor是否胜出。原C1/C2/C3不因本轮
新算法未胜出而消失，也不能因保留原贡献就宣布新算法有优势。最强的研究
表达是指出哪个控制点由哪条证据支持，再交付真实对照；不是把每个结果都
升级为贡献，或把每个负结果都降为措辞问题。
