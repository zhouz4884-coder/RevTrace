## A. R7/R8 可信上下文恢复：新增优先机会验证

- 从正式冻结 R7/R8 代码、配置、128-session 原始证据和完整失败记录核对起。R7 质量尾部 11 个 outlier、R8 部分修复后仍有失败，不得用平均 WER 掩盖。历史源码/环境身份找不到则明确 UNKNOWN，不能以当前 archive HEAD 代替执行源码。
- 首先复算真实问题：相同音频与已授权历史下，缺上下文、数值路径、音频切分、终止预算、适配器重构各自的作用。原 R7 EFSC FAST_COMMIT 是 margin/统计风险合同，不是当前每次 FP32 可信选择；旧“已授权”不自动成为当前严格合同的可信锚点。
- 清查已有 VACC/CSM、same-prompt singleton、长上下文、清空和其他 R8 重锚方案的实际结果，再选择未被既有反证排除的最小恢复操作。不得仅改名为 Capsule。
- 先付费上界与最小原型：完整可信 Canonical 重建、最近真实可信 checkpoint 重放、有限原始音频重锚、简单清空，以及既有有效修复。所有额外模型生成、验证、历史闭合和音频处理都计成本。
- 新恢复仅消费真实受信锚点及已释放原始音频；绑定 parent/frontier、tokenizer/adapter、处理后输入及执行合同。不得恢复被拒 Private 写权限、拼接未经证明的后缀、把 CPU 重解释当新父状态下生成，或用标签/参考转写选择在线动作。
- 先 CPU 安全义务与交错、再真实 GPU same-input/repeat/legal-oracle 对照、再完整服务和全分母质量/成本，最后才独立新来源确认。修复身份必须单独冻结。
- A-GO：在不放松同一可信准入合同下，复现并显著消除所定位的灾难性质量失败，在未用于修复的新来源维持冻结质量要求，同时相对完整可信重建保留有实际意义的端到端成本优势；同样的操作给完整 Standard。有限样本零异常不是普遍质量定理。
- 若只有全量重建有效且无可部署成本空间，或便宜方案仍不能满足质量要求，保留具体 NO-GO，不通过新名称或平均数宣称解决。旧 2.5x/1.9s 等历史门槛保留在原合同，不直接移植到不同 FP32/Consumer/WAL 合同；新联合门槛须在正式独立验证前冻结。

## B. 输入冻结前反馈敏感派发：收紧已有成功标准

- 已实现六种策略与真实开发数据继续保留；修复已定位的 ETA/归因缺陷后，所有策略共享成本模型、等待预算、Row-complete、资源、可信 Render、WAL、Consumer 与原 D2/C8。
- 成功必须闭合因果链：可在线观察的可信更新时机 → 实际模型输入变化 → 支付的 GPU 工作/关键路径改变 → 全 offered 合法服务收益。少发任务、Canonical 已覆盖、组批/padding、普通背压与真正输入介导收益分别报告，不能相互替代。
- 与固定有限等待、pending-Authority ETA、lead/queue 背压、简单 recent-gain、immediate 及完整 Standard 同策略比较；开发预算相同。若普通强基线已获得全部收益，复杂状态控制器不升格为独立增量。
- B-GO 必须来自未用于设计/标定/选择的独立来源、同输入 fresh-process 配对和完整质量/成本审计，而非旧单来源 cap 或单次点估计。正式前冻结最小有意义收益、质量非劣性、统计单位/区间与停止规则；重复不算新来源。若获益仅在旧病理例，报告机制个案并停止扩大性能矩阵。

## 执行优先级与不能混淆的结果

先有界验证 A 的真实质量—成本空间，同时完成 B 已识别修复及小规模公平重跑；只把有可行动空间的一项扩为主要新机制，不重启 Elastic/CES/DAG/V2 等已关路线。
原生 LangGraph 多轮神经写回、参数化/有界形式化、源码身份和独立审计仍在原范围内，已完成结果复用。真实 GPU 任务由一个资源调度点串行管理，不因多代理工作争抢卡。
**R7 上下文恢复**（撤销后生成需要的信息）与**进程崩溃后的可信启动/RTO**是两件事。当前 imports/worker overlap 优化即使缩短 RTO，也不能算 A 的质量修复。
两方向均只能依据实测裁定 GO/NO-GO；目标是努力实现突破，不是把正结果作为必须编造的完成条件。论文主张在验证后更新，不以写作代替机制和证据。
