## Input identity and exact reconstruction recipe

-64sessions per split; seeds2026080701 and2026080702.
- Shuffle each split independently, then deterministic first-fit selection:
  a later utterance may fit where an earlier one would overflow90s.
- Entire utterances only; insert1600 float32 zeros (0.1s at16kHz) between
  utterances. Do not crop the final utterance to make a90s aggregate.
- Pad the remaining tail with zeros when the concatenation is at least75%
  of90s. The recovered128 all yield1440000samples (90s).
- `np.array_split(audio,9)` => nine160000sample/10s windows here. Do not
  concatenate separately decoded text and call it waveform equivalence.
- Original ordered utterance IDs, reconstructed positions and all zero
  separator/tail intervals are saved in `INPUT_IDENTITY.json`.

Outlier sessions: **2,8,22,32,41,54,57,78,90,95,122**. Their original EFSC
physical group is `session_id //16`, with row position `session_id %16`.
They span seven16-row groups. For a faithful GPU rerun, preserve all group
companions and row positions; running only these11 as singleton or a new
batch changes the arithmetic/input realization. Running the original128 is
the simplest unambiguous control. Original Canonical is per-session
singleton; EFSC and Feedback-OFF each execute16-row batches per window.

The actual CPU audit ran in36.10s with no GPU calls, source commit
`eff1047c5aa88d8820d7c593fe254083ccd2607b`, script SHA256
`4eec810fa7620374c9b7b3188d78d7cc85fe9ee9cac09ae73b4477906cdea440`.

## Missing execution evidence and minimum new freeze

The original paired result has no per-window trace. The traced artifact has
Canonical Z and prompt digests, and EFSC candidate Z/termination/action data,
but EFSC stores **prompt token counts**, not full actual P. Counts cannot
establish model-input equivalence. Historical processed tensors, full padding
and decoder-start prefixes, per-call model input digest, weight hashes,
complete loaded-source manifest and per-window physical clocks are absent.

Before any faithful new GPU replication:

1. Choose an actual archived source object (2112157 is the earliest R7
   implementation object; b911e88/2b4eb55 add later tracing/changes), inspect
   its dependency closure, and explicitly document any observer/compatibility
   patch. Freeze a NEW complete source commit, not the mutable old directory.
2. Pin exact policy, input/session/window hashes, model weight format/hash,
   processor/tokenizer assets and execution environment. Run CPU adapter and
   input-layout controls before model execution.
3. Preserve original singleton/batched layouts and all companions, dtype,
   token budget, raw-history cap/reset rules and EOS handling. Do not change
   the baseline merely to reproduce11 bad outcomes.
4. Record full actual P, processed input identity/padding, complete selected
   Z/stop/budget, projected next P, traces and timing. Execute repeated same-
   input controls; compare actual outcomes to the historical text/trace.
5. If outputs differ, keep the difference as source/environment/numerical
   realization uncertainty. Do not repair the historical result in place or
   infer actual GPU regeneration from CPU replay of old Z.

GO: input-reconstruction feasibility and new frozen replication.
UNKNOWN: exact old paired128 GPU execution source/environment/weight identity.
NO: treating current mixed directory or archive HEAD as that old execution.
