# 正文技术主线：跨认证根的合法进展

状态：设计备忘录，待新增实验完成后用于正文。代码依据是冻结源 `f0a8e7bc5fbcb010de28e94ac5c9dbd6e67363cf` 中的 `continuity_proof.py`、`certified_display.py`、`kernel_runtime.py` 与完整事件内核，不是新的模型状态等价算法。

## 对象与假设

Canonical事实包含合同/epoch、版本v、音频前沿F、实际所选完整输出Z、下一次输入状态P及绑定的完整显示文本T。P是声明adapter的完整跨调用反馈状态；本实现不跨调用迁移KV cache。每个Private节点保留实际冻结输入、完整结果、音频边界与依赖身份。相同P的可替换性只在该合同已经声明P与不可变音频/模型参数共同决定下一次调用输入的范围内成立；不推广到未记录的数值缓存或外部工具状态。

## 兼容充分条件

新Canonical推进至F后，旧Private分支可继续提供临时进展，需要：

1. 在同一F处存在完整Private节点，其实际输出反馈P与新Canonical的P逐token相等。
2. 由该边界到分支末端的每条边，实际冻结输入P等于真实前驱的完整输出P；边界按合同连续、依赖可达，合同/epoch/生成代际一致。
3. 分支末端能由这些完整节点实际到达；不能以一个调用方的兼容布尔值代替证据。
4. 任何在途后继仍使用已冻结的链末端输入，目标位于新F之后；不能因Canonical返回而改写已开始任务的输入。

这些条件使旧节点成为新根下仍被允许使用的临时计算。它们不把Private升级成认证事实，不保证Private文本与将来选择相等，也不要求相同输入在独立浮点重复中必然逐位相同。Canonical只接受本次真实受保护选择，依旧经过原授权、WAL和身份检查。

充分条件的证明按边归纳：起点的跨调用状态与新根相同；每条后继使用已记录的前驱输出与不可变输入；重根不修改任何实际调用的依赖或输出。结论是合同内依赖合法性，不是模型语义/概率分布的等价定理。缺少同边界节点、状态不一致、断边或不可达在途输入时保守拒绝。

旧job的出生版本和原始身份仍保留。重根改变的是结果/分支在新根下的使用资格与根引用，不把旧job重写成“当时由新版本派发”，也不据此绕过Authority对本次当前parent的写入检查。

## 为什么计算与Consumer必须一起处理

计算保留R避免把仍合法的链重算；可见保留S在Canonical应用时检查当前完整临时假设是否仍兼容，兼容且位于F之后就保留原假设，同时独立推进认证lane；不兼容就撤销。它不拼接一个未经证明的文本后缀，也不从音频前沿推断token对齐。

条件性性质：若一次Canonical应用前的完整可见假设位于新F之后且兼容，S不会仅因该Canonical到达而将其替换为较短快照。后续其他发布仍可能修订文本或改变前沿，因此不声称无条件单调可见性。R关闭时，后续重算可能再次发布较短但合法的假设；S关闭时，Canonical应用会丢掉已见兼容进展。严格四臂正是检验这两种边界损失及联合服务效果。

### 同一状态合同，不等于两个检查器逐字相同

计算端 `eligible_chain` 采用完整同边界节点、链末端与在途输入的保守充分检查。Consumer 只处理完整已发布的视图，并可直接使用“该完整调用的冻结输入恰在新F处等于新P”的证据；这种路径不必再要求一个额外Private同边界完成节点。现有12个CPU见证已明确展示二者区别。因此正文应写共同的**声明反馈状态与实际冻结依赖关系**，分别解释R/S如何提供足够见证；不能写两处复用完全相同的guard函数、或把某一实现多要求的节点证明成所有实现的必要信息。

抽象关系可从新Canonical本身作为起点定义：第一条后继的真实冻结输入对应新F/P，随后每条实际边消费真实前驱输出；旧Private节点只是证明第一条输入可重根的一种见证。R进一步限制其可保留集合，不影响充分性。Consumer不处理未完成的行，也不因保留合法依赖而认证临时识别内容。

## 退休是另一类谓词

当前K只在真实已安装Canonical.F覆盖Proposal目标、且该任务在声明用途模型中不再承担剩余用途时请求退出。它与上面的兼容关系分别回答“仍可用”和“已无用途”；不是同一判据。原accepted输入义务、原始期限和Canonical处理继续存在，不因CancelRequest或RowCancelled而清零。

CancelRequest仅发出请求；Worker在支持的decode边界观察；RowCancelled只报告计数，不提供部分状态；RowComplete提供完整结果，二者互斥；所有行有终态且设备同步后才发BatchDrained并释放lease。静态batch不做压缩/补位，屏蔽行的残余成本仍计入。没有声明任意GPU故障下的毫秒取消上界。

## 正文要保留的四个最小交错

1. 旧root、同边界P相等、可达完整后继：R可继续，S可保留完整临时视图。
2. 旧root、同边界P不同：必须撤销；少回撤不能靠继续显示不合法文本取得。
3. 没有已见ahead：四臂可能自然接近，零回撤并不证明有收益。
4. 目标已被真实Canonical覆盖但物理执行仍占用：K可以请求安全点退出；只有真实drain才恢复执行时隙。

实际新增R×K实验要判断第1与第4的服务价值是否相互增强。可分离也完成了问题，不为交互显著另造退休原因。
