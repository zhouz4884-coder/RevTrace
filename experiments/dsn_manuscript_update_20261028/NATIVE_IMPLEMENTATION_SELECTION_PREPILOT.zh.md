# 在线pilot之前：选择完整设计的实现，不要求某条代码独占成功

2026-10-29。本决策写于新source0三臂pilot实际运行之前。三个执行臂的名称、身份和测量口径不因此更改。

本轮有两层问题，应分别作决策。

**第一层是系统贡献。** 在原反馈纠错任务、原C/U与相同两卡资源上，完整反馈依赖的推测执行、在途资格保留及实际whole-view协调，能否带来更好的服务。`two_full_spec_early`是我们为此新构造的整调用推测实现，`ready_handoff`是我们构造的阶段实现。二者都使用完整输入/实际父根/epoch，而非外部已有系统碰巧提供的完整原创组合。它们之一更好或同效，不能自动反证这个组合的应用价值。不能把胜出的自建实现硬留作“外部强基线”，然后据此宣告自己的研究没有机会。

**第二层是实现选择。** 阶段交接相对完整调用推测是否还有额外的时序/成本收益，需要直接测量。仅赢保守串行不足以证明阶段粒度独有优势。阶段法没有赢时，不得把小差异写成其优越性；如整调用实现效果最好，可以透明地选择它作为本设计在native应用中的实现，完整报告阶段实现及其边界。主论文仍需以R/S因子分解和独立来源证据支撑设计，而非依靠重新命名基线制造优势。

## 有限决策树

固定旧source0、三臂各1fresh随机pilot。实现/完整状态/原选择保真全部必须先通过。原D2/C8、全部offered、文本端点、能耗不改。

机会筛选门限（非显著性检验）：相对比较对象，至少新增0.5s原双期限信用；或信用和整场通过状态相同、median认证延迟同时减少100ms且10%；或service双板能耗减少10%。阶段特有优势的比较对象为`two_full_spec_early`；完整组合服务机会的比较对象为`two_full_early`。模型加载/预热成本另列，不能替代service收益。

若无设计实现达到有意义的服务机会，完成证据化停止。若只有一个实现显示明确机会，下一轮冻结四个旧来源、每来源两fresh、它与保守两full对照的16格；阶段相对fullspec的额外优势仍单独报告。若两种实现实质接近而取舍尚未清楚，可在同一四源两重复中保留三臂，共24格，不重复两套16格。只允许原source0三臂再完整重复一次解决临界噪声，不通过换源/换相位寻找过门结果。

若ready-only失败主要由同输入在途A被重复fallback解释，且仍有端到端空间，可依据[预先记录的在途假设](STAGE_INFLIGHT_HYPOTHESIS_20261029.zh.md)决定一次最小join修补；它需要新的执行冻结和同输入控制，不把旧source/结果重标。没有该实际证据就不实现。

只有最终实现冻结且旧源确认值得支持独立性时，才metadata-first、speaker-disjoint选择少量新来源并冻结两臂确认。旧四源始终是开发数据。饱和双会话的容量边界是另一层描述性控制，不得为了其过D2而改变合同。

论文应肯定具体系统设计，同时透明承认实现替代和共同原理。我们选择有竞争力的贡献与必要证据，不选择性删除反例，不宣称某个实现必须胜出，也不将多个作者自建完整实现的同效误作外部先例。
