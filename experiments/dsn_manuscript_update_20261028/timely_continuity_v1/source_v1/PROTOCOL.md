# Timely delivered progress: subsequent continuity

This is a post-hoc secondary read-only analysis of all 36 frozen service runs.
It is not a new deployed credit, new neural execution, or replacement of the
original D2/C8 first-observation credit. The existing raw logs remain on the
designated experiment disk. Analysis reads only actual Consumer observations,
original audited offered frontiers, and existing independently reconstructed
consumer-apply compatibility witnesses.

For each original offered audio interval i, retain its original weight and
first actual visible/first certified times. Eligibility q_i means that these
unchanged observations satisfy original D2 and C8, including partial EOS
intervals. It does not certify provisional content or make future Canonical
agreement an online test.

At an actual Canonical application u, compare the adjacent actual Consumer
views. For every original interval that was visible before u and not after u,
record its q_i and the full-view compatibility witness at u. Compatible loss
and incompatible necessary loss are reported separately; unresolved evidence
is UNKNOWN. A compatible whole view is still provisional.

For every q_i loss, measure from u until the first subsequent actual Consumer
view covering i OR the next Canonical application for that session, whichever
comes first. If the next Canonical still does not cover i, mark the window
right-censored: legality under the first root must not be silently extended to
an unchecked later root. A recovering Canonical is a recovery at that exact
time. These single-root windows cannot overlap for a given interval. Report
weight times observed deficit duration (audio-second x wall-second), actual
interval and event counts, duration maximum, and right-censored counts.

Also report whether the original fixed Display deadline ready_i+2 falls in
such a deficit window. This is an observation at a fixed original deadline,
not a counterfactual user study. Keep the original first credit unchanged.

The strongest comparison is Joint versus compute-only, with all four arms,
three workloads and all three repetitions retained. Run-level paired results
are descriptive; repeated fronts are not independent speakers or deployments.
No new confidence interval or parameter search is introduced.

Stop after all 36 runs. A zero timely-compatible loss is a complete negative
result and narrows the service significance; it must not lead to changing D2,
selecting a source, or launching GPU runs. Input identity, independent first
times, 3204 Canonical boundaries, all original denominators, and every drop
must reconcile. Unknown/censoring are explicit rather than counted as success.
