# 本轮真正接入了什么

冻结 Runtime：`e45c66475ba1173a98b49b8c9e62f3e8cb45b333`。
本文件解释实现，不宣称正式 GPU 性能已通过；数值结论以最终独立报告为准。

## 1. 旧 GPU 版本与本轮的区别

此前 48 单元版本已使用实际 Consumer ACK、风险成本、逐行完成分布、残余收益目标及拆批选择。
但 CPU 设计中的后继期限回传及跨重规划服务义务尚未进入实际派发回路。
因此旧版本的性能失败不能被称为完整闭环算法的 GPU 失败。
本轮将两者接入真实 Owner → 同构物理 Batch → Worker → 收据 → WAL → Consumer 回路；
同时补入当前与已释放后继的合法 Private/Canonical 双路径预测。
源码、测试、可观测字段的逐项对应见 `IMPLEMENTATION_COVERAGE.md`。

## 2. 目标不是“少做认证”，而是按时完成合法音频进展

对音频前沿 q，音频权重为 a_q，释放时刻为 r_q。冻结的两个期限是
`d_D(q)=r_q+2s`、`d_C(q)=r_q+8s`。本轮主读数为：

`Q = sum_q a_q * 1[第一次合法显示 <= d_D(q)] * 1[耐久提交 <= d_C(q)]`，

`Audio Goodput = Q / 实际整次运行时长`。

显示已达标、认证仍待完成的音频依然有可挽救价值；显示已逾期的音频不能被迟到认证改记为达标。
后者虽然没有自身双期限收益，却可能是另一个已释放且仍可达标前沿的必要前驱。
第一次合法显示、持续有效显示和实际认证 Consumer 应用分别报告，不混成同一指标。

## 3. 后继期限回传

目前只展开最多两层已经释放的后继。若后继 u 的合法路径必须依赖当前转换 q，
且从 q 完成到 u 满足相应期限的预测剩余工作为 L(q,u)，则 q 可继承近似期限：

`d_inherit(q,u) = d_required(u) - L(q,u)`。

这不是把后继伪装成已可执行任务。未来真实 Parent 未产生时，后继只是 Session/音频边界/
期限/成本组成的调度对象。真正 Job 只能在真实前驱通过认证和 WAL 安装之后构造。

候选计划排序使用继承期限；完整评分另外计算同一有界工作集合上的收益和成本。
Private 路径可独立及时显示时，Authority 并非必然的 Display 前驱；这部分由双路径评分处理。
继承排序本身是启发式，不是所有资源条件下的精确最迟开始时间定理。

## 4. 避免“每轮都承诺下一批、但一直不执行”

服务记录绑定 Session、运行纪元、真实 Parent 版本和摘要、音频区间及执行契约。
只有实际成功提交给物理 Worker 的动作才增加派发/推迟计数，空轮询不算一次服务。

第一次选中完整计划后，未派发后缀保留预测完成承诺：

`promise(q) = P90[该已选计划下 q 的行完成时间 + Owner 交付]`。

后续重规划不能悄悄把同一承诺往后移动；预测无法满足时记录违约风险和实际违约。
连续被其他实际 Batch 推迟两次的同身份可执行目标触发服务保护。
这避免了旧版本见证中的反复后缀替换，但不保证过载 GPU 上仍能满足 2/8 秒 SLO。
这些是性能状态，不是写授权。重启不会凭这些记录产生认证权限或持久化期限保证。

## 5. 将 Private 与 Canonical 作为两条不同的真实路径

Display 的预测时刻来自 `min(合法 Private Consumer 应用, Canonical 发布)`，
不是简单等同于 Authority 完成。

已观察收益只由真实 ACK 建立；未来 Private 预测只使用确实在途的 Job、冻结输入、
已观察 Worker 启动时钟和实测行完成分布。缓存中已撤回的文本不是可免费重发机会。
Worker 起始时刻未知时不能把 enqueue 以来的时间全算成已经执行的 GPU 进展。

对于候选 Verify 成功分支，在正确目标 Parent 下用 Trusted Render 计算投影，
再通过已有 exact-chain 谓词只读检查真实 Private 链是否兼容。
该条件预览不能代替 FP32 验证，更不能直接发布或写入状态。

Direct Generation 与 Fallback 的结果在执行前未知，不能自动赋予“不兼容”概率 1。
本轮分别使用历史实际选择中可支持的条件性根投影相等统计；样本稀疏时保留 unknown。
第一层可用当前转换模型；未知更深 Parent 不得继承根层兼容性结论。
这些统计是选中操作的经验数据，不是对未选操作的真实反事实。

## 6. 计划评分、物理执行与可计算的界限

对共享完整工作集合的一条有界计划 pi，使用场景条件下的有限前缀目标：

`E[(Q_observed + DeltaQ(pi)) / (T_observed + DeltaT(pi))]`。

Verify 分支包含真实拒绝概率、完整 FP32 Fallback 和所有物理 Lease；
不能把 Verify 与 Generate 两种异构调用算成一个免费 Batch。
行提前完成可供合法消费，但 Batch 未排空时 Worker 仍不可复用。
两张 GPU 的并行时间按实际执行路径处理，不能直接相加成墙钟“节省”。

执行策略先比较服务保护和既有承诺违约，再比较上述收益目标及真实工作成本。
这意味着最终策略并非无约束最大化 Goodput：它还维护已作出的服务义务。
若该取舍损害实际 Goodput，必须如实报告，不能称安全保证自动产生性能优势。

搜索初始上限：8 个候选完整计划、最多两种后继交错、16 个场景组合、两层已释放后继。
Private 完成分布最多压缩至 32 个加权上端点，保留全部概率质量并记录 CDF 误差界。
这些是有界在线启发式，不是全局最优联合调度算法。

GPU0 的真实子批次选择共享给适用基线。候选对 GPU1 的价值只在实际占用的 Authority
Lease 后建模，不假装空闲 GPU1 会自动等待尚未生成的候选。
该 GPU0/GPU1 联动是顺序有界规则，不是同时求解任意未来到达的完整策略树。

## 7. 为什么预测错误不会直接变成非法状态写入

调度器只选择当前允许的认证计算。实际结果仍经过原来的 Parent、Frontier、Contract、
完整 Token/Stop、D1 Trusted Render、单 Owner 和 WAL 检查。预测不创建证书。
在原信任 Worker、互斥写及存储成功假设下，对被接受转换归纳，原准入不变量不因
调度预测错误而改变。此论证不等于可用性、内容完整性、任意期限或预测准确性的保证。

## 8. 正式比较能回答什么

- `reserved_progress → inherit`：同类有界收益规划加入已释放后继的价值。
- `inherit → causal`：在上述基础上增加合法 Private 双路径预测。
- `causal → causal_joint`：改变实际 GPU0 选择，必须同时看 `cost → cost_joint`。
- Fine/Standard 的 `ready → shared_progress`：共有 Proposer 拆批能力是否已经解释收益。
- Full 对 Fine、Standard、Cost：完整系统是否真正改善，而非只比某个削弱消融好。

本轮 72 单元没有完全相同新规划器仅关闭服务保护的纯消融；不能将旧 48 单元进展策略
或新 Cost-only 直接叫作该单因素对照。旧实际音频池已用于标定，因此本轮是重复的
机制诊断，不是新来源的独立确认。性能成立与否以真实 GPU 结果为准。
