# 正式72单元的独立结果复核

结论：本轮完整 closed-loop CES 仍应判为 **NO-GO：尚不足以作为广泛的 C2 性能升级**。
这不是准入失败：提供的 v2 审计汇总为72/72 PASS。问题是完整 causal 没有稳定超过
强 Fine/Cost，错峰明显落后；causal_joint 进一步损失 Goodput。与此同时，后继感知与
Private 建模在错峰的新方法家族内部有三次同方向的局部正信号，不能将其抹掉，也不能
将其放大为已超过强参考的独占算法贡献。

本文只独立复算已提供 CSV 的算术、分组、配对和分母。不重新执行神经模型，也不把
审计汇总中的 PASS 当成本文重新完成了全部 raw 证书/输入/WAL 审计。后续真实事件
关键路径复核仍需单列。未改原数据、Runtime、控制器、参数或正文。

## 3. 必须保留的两种效应口径

配对效应先在同一repeat内计算 `100*(treatment/control-1)`，再对三次取中位数。
组中位数之比则先对两组各自取中位数、再相除。它们不等价，甚至可异号：

| 同步比较 | 三次配对变化(%) | 配对中位变化 | 组中位数之比变化 |
|---|---|---:|---:|
| causal / Fine | +0.0063, -3.7387, +0.6281 | +0.0063% | -0.5427% |
| causal / Cost | +2.5598, -0.8411, -0.9210 | -0.8411% | +1.9968% |

因此不能用最后一列写成“causal相对Cost稳定提升2%”，也不能把接近零的Fine比较
写成实际系统收益已经成立。

下表的区间是对三个已观察配对效应进行全部27种有放回重采样所得的描述性95%区间。
在n=3下这里基本退化为观察最小/最大效应；不是独立来源确认、不是多重检验校正，也
不是分布无关的性能保证。

## 5. 分项方法有无值得保留的信号

| 干预 | 同步Goodput配对变化 | 错峰Goodput配对变化 | 限制 |
|---|---:|---:|---|
| service_cost → reserved_progress | +5.362%，区间含负值 | -17.523%，三次均负 | 有限前缀目标没有稳健改善共享成本/服务保护参考 |
| reserved_progress → inherit | +1.517%，区间含负值 | +7.357%，三次均正 | 错峰C99配对+15.341%；这是后继机制包，不是单独回传算子的消融 |
| inherit → causal | -0.904%，区间跨零 | +7.040%，三次均正 | 错峰C99配对+18.615%；新家族内改善仍远低Fine/Cost |
| Fine → shared_progress | -7.719%，三次均负 | -0.945%，区间跨零 | 同步D99改善约8.0%，却损失双期限Goodput |
| Standard → shared_progress | -7.290%，三次均负 | -9.888%，区间跨零 | 共享能力并非自动增强系统表现 |
| Cost → joint | -6.175%，三次均负 | -5.001%，区间跨零 | 不能把共同执行器能力记为CES独占创新 |
| causal → joint | -11.029%，三次均负 | -7.575%，三次均负 | 当前联合策略没有通过净收益门槛 |

两个错峰局部正信号是真实的配对方向，值得保留作为机制诊断：后继包相对reserved、
Private包相对inherit均三次提高Goodput。但这只是从较差的新家族基点向上恢复。
它没有解决“比强Fine/Cost有何系统收益”的主问题，也没有在同步复现同方向增量。

当前最有力的共享执行器结论反而是一个权衡：同步四个GPU0副臂都减少了Display P99，
但四组Goodput均三次下降。不能把降低P99本身写成无代价的系统升级。错峰Causal+joint
相对causal又使Goodput配对-7.575%、GPU能耗+5.078%，显示当前候选价值/子批策略没有
形成足够强的联合进展收益。

## 6. 质量、SLO与完整成本

所有72个run的聚合WER都是2.037845706%、CER都是0.644745326%，所给CSV中
未完成来源为0、Authority触顶准入为0。这说明**被记录的这些聚合质量数没有差异**，
不证明Token/Canonical History逐位相等，也不证明不存在Proposer触顶或其他未提供的
内容缺陷。不能将Authority cap=0扩大成两条时间线均无cap。

全体整run双P99通过0/72，仍有大量前沿按时完成；两句话并不矛盾。不能把正Goodput
当成2s/8s容量SLO通过，也不能将全部miss改说成所有请求失败。

实际F2消费数在run间出现6、7、8，不能把冻结外生目标映射等同于所有方法实际消费了
完全一样数量的故障。该数量属于真实调度结果，需要和冻结目标数分别报告，不能事后
筛音频来“配平”。

错峰的几个直接成本观测如下（组三次中位数）：

| 指标 | Fine | causal |
|---|---:|---:|
| 全run wall(s) | 24.083 | 28.896 |
| Authority planner累计wall(s) | 0.0000645 | 1.468 |
| Authority Worker service(s) | 21.374 | 23.296 |
| Proposer Worker service(s) | 21.200 | 26.675 |
| Proposer实际模型调用数 | 21 | 15 |

这里的约5.5s Proposer service增加不能被简单解释成“更多物理batch”，因为调用数的
组中位数反而更少。可能涉及批内行组成、Token长度、上下文、等待、cap或尾部；需要
逐条raw检查。也不能把1.468s planner wall直接从run wall中扣除来模拟免费CPU优化。
两设备重叠、Owner收据处理、到达和Parent可用性使这种减法不是合法反事实。

## 7. 冻结源码的预测视野边界

为回应成本线索，另外只读核对了 e45 中的两个文件，字节未变：

- `runtime/src/revtrace/ces_closed_loop.py`：SHA
  `2226264d46153f7db269f83364810d17fbe169386f9b48e5ff5b0d9cb0dda66e`。
- `runtime/src/revtrace/ces_closed_loop_owner.py`：SHA
  `450ac323118968e904589f202283802c054569e25c1fbc81fbb129c196a7d9b0`。

`_expanded`（459行起）只加入当前Authority批与最多两层symbolic FP32后继生成。
`_evaluate`（568行起）为这些GPU1 steps累加物理lease，Private路径则读取已经派发的
实际pending job的剩余完成CDF。它没有在一个GPU1动作的预测中，计入该动作等待期间
**尚未派发、随后可能因为Authority滞后而启动的GPU0工作及其尾部成本**。

Owner的 `_closed_proposal_selection`（282行起）单独为当前ready Proposer cut的完整
两批计价；joint在已有真实Authority占用时增加当前候选就绪价值。它不是联合滚动
模拟两设备今后全部新派发工作的状态耦合模型。

因此保留一个**待raw验证的假设**：Authority排序/推迟改变了随后实际启动的Private
工作、批形状或私有链尾部，使GPU1局部预测低估了双时间线的闭环成本。这个假设
与当前代码视野和服务时间数据相容，但还不是根因结论。

验证应在同一Session/音频前沿上逐条核对：真实派发/Owner排队、Parent和Private根、
批成员与物理lease、输入/输出Token长度、EOS/cap、obsolete/rebase时点及实际Consumer
覆盖。尤其要区分新增row、不同合批尾部和单行变长，不把重叠服务时间重复加到关键
路径上。若真实数据不支持滞后诱发更多/更长Private工作的解释，应撤回这一解释，
而不是靠重命名算法维持它。

## 8. GO/NO-GO判断

| 主张 | 当前判断 |
|---|---|
| 实现确实接入闭环服务义务/后继/Private模型 | 实现与给定v2审计记录支持，不能再称本轮只跑了前一版 |
| 完整causal已成为超过强参考的稳健C2算法升级 | **NO-GO** |
| causal_joint提供独立净系统收益 | **NO-GO** |
| 错峰后继包和Private包在新方法家族内存在局部收益 | 有限诊断正信号，需保留；不等于主贡献门槛已过 |
| 同步存在小幅同聚合质量节能点 | 对Fine可如实报告；对Cost不稳健，C99与另一到达负载代价不能省略 |
| 这些结果否定原C1/C2/C3或证明组合机制不能创新 | 不支持这种推断 |

本轮没有纯“去掉service guard、其他完全不变”的GPU消融。旧48单元、旧cost模型或
Fine都不能冒充这个对照，因此即使某个跨campaign尾延迟改善，也不能独归因于guard。
来源池已用于诊断/拟合，不是新held-out。三重复结论只限本次被测条件，不能写成
已证DSN竞争力提升、普适最优或录用概率保证。
