# 原生R×S：结果解释规则与最终报告模板

本笔记只解释已冻结实验的估计对象与结果读法，不修改运行时、controller或论文，不调用GPU。以下规则不以某个臂必须获胜为前提，也不使用录用概率或审稿分数。

## 1. 因子、锚点与样本单位

冻结配置把四臂定义为：

| 因子臂 | R：原始调用保留策略 | S：实际Consumer在Canonical应用时保留兼容ahead视图 |
|---|---|---|
| r0s0 | Ready-only，只复用已接收完整结果；未决调用围栏/重派 | 关闭保留，回到认证快照 |
| r0s1 | 同一Ready-only | 开启兼容保留 |
| r1s0 | Fullcall，保留输入后来确认的在飞完整原调用 | 关闭保留 |
| r1s1 | 同一Fullcall | 开启兼容保留 |

Conservative/S1是另一个无投机锚点，不是四臂中的R0。所有臂继续验证完整输入、原始C/U选择、持久事实/身份与Private完整依赖路径。S0不等于关闭SUP安全校验，而是使用更保守的视图替换策略；它仍允许合法Private首次发布。

完整范围是同一既有8说话人×5条件×2fresh-process重复，80个trial；前2人20格pilot、后6人60格确认。80个trial不是80个独立声学样本，旧研究中的同八人也不能追加到n。说话人是比较单位；每个source的两个时序重复先保持在同一个cluster内，具体窗口/前沿/应用事件只增加观测，不增加独立n。

## 2. 先分开技术完成与科学结果

技术完成要求：

1. 实际完整源码/配置/环境身份与冻结计划相符，全部预定格均有记录；失败、timeout、SLO miss均保留。
2. 每个实际选定transition的完整状态、原纠错与返回IDs匹配新strict reference；实际Consumer路径与row、模式字段和durable事实一致。
3. 派发/安装/放弃/晚丢及物理终态账闭合；worker时长与缺测神经阶段分开；两板能量窗口到确认物理drain，启动/参照单列。
4. 能量有外部所有权证据；若发生外来GPU负载，明确标注该energy列的有效性，不能把未证实的J写成节能结果。

技术PASS不要求出现S机会、正交互、SLO通过或RevTrace获胜。反之，技术失败不能被当作负效应来代替修复/保留/停止的执行判定。以现有冻结protocol的continuation和gate执行，不因结果方向挑source或择优重跑。

## 3. 先看机制机会，再解释S效应

S机会的计数是**实际Canonical应用前，非空实际视图ahead于该Canonical，且其完整依赖边界与该实际Canonical匹配**。至少报告每臂、每来源：机会数、保留数、可避免下降数、完整边界反证导致的下降数、缺少边界见证的下降数。机会是应用边界计数，不是去重view身份或自然失效率。

| 完整数据中的观测 | 可以建立的结论 | 不能由此推出的结论 |
|---|---|---|
| S0实际清除完整支持的ahead view，S1实际保留；选定原任务不变 | 在同一原生实现中，S把某些仍合法的已交付进展保留下来；局部损失可由S0自己的完整旧路径与新事实核验 | 两个闭环运行拥有完全相同的候选/事件时序；所有信用差都由该次保留造成 |
| 有机会，S0有可避免下降，而首次信用近似 | 连续可用性与首次交付确有独立效果；保留已及时内容不必改变首次信用 | S无价值；或首次信用相同就代表交付过程相同 |
| S0下降后Owner紧随的Private快照迅速恢复 | 实际Consumer存在短暂的合法进展缺口；应给真实时长、面积及分布 | 该view一定要等下一次模型完成才回来；逻辑缺口等同于人眼可感知闪烁 |
| 所有S对照均无兼容ahead机会，且无视图损失 | 这个工作点没有激活所测试的兼容视图保留机制；CPU合法性控制与现场模式绑定仍可通过 | S的原则冗余、两个策略普遍等价、或零机会说明程序没有执行S0 |
| 没有S机会，但两S臂首次信用有差异 | 记录这个闭环执行的端点差与时序变化，保留它作为测量结果 | 把差值直接归因为“避免了兼容view撤回” |
| 有完整边界反证且两S均撤回 | 共享支持检查在原生执行中阻止无支持保留 | 必要撤回也应被S消除，或所有rollback都代表协议错误 |
| 有机会但缺少足够实际原始记录作支持分类 | 标为unknown并补齐审计；保留原始事件和端点 | 将unknown并入necessary或零违规 |

**立即重发布尤其重要。** Owner在Canonical后还发布`view_event_snapshot`，而S0并不禁止后续合法Private发布。因此S的主要效果可能体现为一次Canonical→Private实际应用间隙，而非整秒级的模型重算。只有实际Consumer观测能确定窗口；Owner emit、worker model_end或socket到达不是替代的显示时间。

## 4. 信用、回撤面积与资源各自报告

### 首次期限信用

每个原offered区间按其音频权重，只在首次实际显示D2和原认证C8同时满足时计一次。撤回不扣回首次事件信用，恢复不重新计分。S可以减少可避免损失而不改变`A2,8`，亦可能在不同真实调度下获得不同的首次信用。

对于同source、同repeat四臂，令`Yrs`为同分母上的实际信用音频秒或预先说明的信用比例：

- S在R=1时的简单效应：`Y11 − Y10`。
- S在R=0时的简单效应：`Y01 − Y00`。
- R在S=1时的简单效应：`Y11 − Y01`。
- R在S=0时的简单效应：`Y10 − Y00`。
- 四臂交互：`I = Y11 − Y10 − Y01 + Y00`。

必须同时给直接简单效应和交互。I为正并不要求Joint−Compute为正；I为负也不抹掉某次合法视图保留。对损失数/面积，较小为好，不能机械套用“正交互必有利”的方向。总音频秒差、pooled比例差、平均source比例差是不同统计量，别将一种的区间挂到另一种上。

### 两本Gap账

1. **全体高水位缺失面积**：按source历史可见frontier高水位与实际可见frontier之差，对原观测时间积分到显式service end，单位audio-s×wall-s。这与H3总Gap口径相近，包含必要或unknown撤回。
2. **支持分类的同root窗口面积**：从实际已分类的下降开始，到恢复其旧frontier或下次Canonical/Owner-epoch边界为止，保留截断/右删失和实际恢复标记。可避免同root面积仅量仍有当前完整支持的窗口；没有凭未来root重建一条完整跨root合法G。

分类窗口面积不一定构成总高水位面积的分区，跨分类窗口也可能有重叠。总量不可直接从每个episode相加；应给审计器实际实现的union与非加性说明。`removed_audio_seconds`是相邻frontier下降量累计，同一音频可能在多次下降中重现，不能除以offered后称去重丢失比例。恢复frontier也不自动等于逐字文本恢复。

### 工作与能量

实际worker-job占用是host elapsed work，不叫GPU active time；中止调用的缺失infer计时保留unknown。能量按相同两块板、同service-origin→确认physical-drain口径比较，报告每臂总J、J/offered-audio-s以及逐source配对方向。启动和参照成本另列，不能把它们的变化算成协议节能。

Conservative/S1提供新的**同源、同运行时、同参考、同硬件**锚点，避免把旧Conservative和新Ready相减后命名为缓存净收益。但即使新比较中Ready与Conservative接近，其差仍代表两套完整派发/取消/复用策略，不是对“完成缓存本身”的独立因果估计。若Full比Ready少工作、比Conservative多工作，应如实呈现有用提前执行的代价和期限收益，而不是强行拼三角全维支配。

## 5. 截至first-three快照仅能作什么判断

`baseline/PILOT_FIRST_TIMINGS.json`当次读取含3个已完成格，均为S0769的repeat1；有r0s1、r1s0、r0s0，r1s1及Conservative尚不在这份快照中。因此不能计算完整四臂交互或得出pilot科学结论。

这三格都记录17次Canonical应用、0次兼容ahead应用。r0s1与r0s0信用相差0.5audio-s，尚无兼容view保留事件可将该差命名为S连续性收益。它们的实际启动为50.786–89.361s、正常service为14.864–25.865s；这些只帮助估计执行墙钟，不用于识别某种加载原因、算法税或时序稳定性。

后续必须用完整冻结pilot表替代此临时快照；这三个格的观测不得成为删源、挑重复或调整deadline的理由。

## 6. 最终结果报告模板

### 执行与身份

- 完成/计划trial数、失败及SLO miss；实际runtime/driver/auditor commit与manifest；原始结果位置和gate。
- 本轮同8个既有source，2个fresh重复；pilot2与confirmation6分开列明。
- 原完整状态/C/IDs参考与实际Consumer全路径审计结果；模型/资产/环境身份和物理排空记录。

### 一张五臂主表

每臂：全部offered、信用秒/比例、整run通过数、worker-s、两板J、兼容ahead机会数、可避免/必要/unknown撤回数、累计removed audio-s、总高水位Gap、同root可避免Gap及其恢复/截断/删失计数。

### 两项关键分解

1. 同source/repeat的S简单效应与四臂交互；按source合并重复后的方向与范围。
2. 选一至数个真实S0兼容损失事件，串起旧完整视图、新Canonical支持、实际下降、实际Private恢复与期限读点。若无这类事件，直接呈现零机会及其调用/发布时间关系。

### 核心解释句

> 本轮在共同原任务与安全检查下，实际比较了在飞计算保留和兼容整视图保留两个动作。结果表明：[完整数据支持的R结果]；S在[实测机会与实际时间尺度]下[实测结果]。Conservative锚点显示[同口径服务/工作/能量对照]。

### 对竞争力的判断

- 若出现完整支持下的S0损失且S1保留，实验把“core解释S、native解释R”的两段证据连接为同一个原生系统内的机制分解。
- 若原生S机会很少或窗口很短，实验提供准确的原生工作点边界和可比较的Conservative成本锚点；它不会凭空升级为原生S普遍显著收益。
- 对任一结局，原任务不变、真实时钟与完整成本、反向/零结果保留和可复核机制定位均有价值。不要用实验是否“赢”替代以上具体论证，也不要给未经校准的录用概率或分数。
