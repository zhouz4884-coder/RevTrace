# RevTrace LP1：下一周有界研究结项

实验 ID：REVTRACE-LP1-20261026；结项：2026-10-27（香港时间）。
基线：公开 main `62b1003c2db6766118244c78fa95e2c3fac42c16`，实际 CK5 runtime
`b8aa802c687256d3801612dc8bee585ee849ddea`。未修改论文、标题、摘要或参考文献。

## 核心判断

本轮有真实、可复核的补强，但三项不能混记成一个独占算法：

1. **历史选择存在真实完整性缺口**，已实现安全查询和完整入口回归；普通多版本索引同样解决，尚无独立索引/保留算法优势或新增2秒 Goodput 证据。
2. **当前输入 KV 前缀续写能省实际执行成本**，并已通过真实服务审计。完整 Standard 使用相同执行器几乎同效，收益属于共有执行优化，不是 RevTrace 独占解码创新。
3. **状态准入阻止了实际未来任务损害**：低信任相干替换在读集仍有效时越过 OCC，进入真实数据库和后续模型输入。可信选择阻断这条路径。内容-only 控制已排除 JSON 排版混杂；正确状态仍可能得到错误答案，未隐瞒。

## S：历史兼容预览

按真实 host 接收、验证、发布、Consumer 应用时钟扫描旧 GPU 原始记录，未用 GPU 完成时间提前获知结果。

- CK5：136 次尝试、2,948 次 canonical 更新，0 个历史选择改善。
- N5：151 次尝试、9,442 次 canonical 更新，14 个已发布历史预览改善，分布为三条运行的11/1/2。不是14个独立来源，也不是自然总体发生率。
- 六种查询/保留配置通过真实 FIFO 的 CPU 重应用；原始 kernel 对这14个实际 Job/P/Z/文本的检查均通过。
- 14 个机会均不能新增原时钟下首次2秒显示信用。12 个未发布候选上界经代际撤销复核全部不合法，不能复用来制造收益。
- 完整 native dispatch→Render→真实 Input/Canonical WAL→发布→kernel→Consumer 的 CPU fixture 跑通：同一 canonical 前沿960，原生 latest/two-register 显示960，扫描/索引等显示1120。模型是声明的 SCRIPTED CPU adapter，不是神经 GPU 实测或6/12/14/16秒结果。
- 当前实现只承诺 Consumer 已登记、当前权限有效且同时通过 native 与最终 kernel 关系的最大合法预览；不承诺任意未发布 host 结果的全局最大值。两槽对照是原生 canonical/private 语义的别名，不多算一个独立算法。

安全保留有明确条件：不得删除祖先歧义证据；单独撤销/未封闭图默认禁用语义支配删除；已知代际退出不能因恢复 NORMAL 而复活。最终源码还补了 native 分支内关系与 generic kernel 跨分支歧义关系的联合过滤。普通强索引匹配完整扫描，**独立新索引/保留算法 NO-GO**；实现回归与合法进展性质 GO。

## X：当前输入 KV 续写与真实成本

独立实现 HF/eager 的标准 prefix-accept→crop→可信 bonus→残余生成，不接收旧上下文 KV。共享音频编码/末行投影优化也提供给 Fresh 和 Strict；不是把弱 Fresh 重复编码当基线。VoiceAgent 原生源码已检查并致谢，但其 FlashAttention 环境不可用，未声称复现原生引擎速度，也未分发其无根许可证源码。

### 第一门槛：32个配对目标算子

8个实际音频来源 × 固定ρ∈{1,3} ×2次重复。候选按原始真实 ready cut 冻结，不按未来匹配长度挑选；每种方法都重新运行、计入 FP16 Proposer。
24项先导控制、32个目标×4方法均通过完整 Z/P/文本/Stop 核对。含实际 Proposer 的同步算子执行时长，prefix/Fresh 的来源聚类均值比为0.853（ρ1）和0.547（ρ3）。这些是给定冻结 Parent 的**算子口径**，不是部署吞吐或能耗降幅。

### 第二门槛：16次真实服务

2个按元数据顺序选取的完整独立音频，双 RTX3090，FP16 P0/FP32 A1，physical microbatch1，偏移0/0.25秒，固定2秒 fine，D=2s/C=8s，真实 Row-complete、WAL、kernel、Consumer 和外部双 GPU 功率采样。
4方法×2种固定ρ×2次 fresh-process 重复。下表为两次运行中位数；这是**低并发开发点，不是 held-out 容量结论**。

此外另付48个逻辑目标调用，检查16个实际服务 Parent：完整处理后张量身份一致，native 同输入重复、原结果及相同执行器重执行均一致。这是单列 GPU 诊断，不计为免费服务收益。有限精度的全球位等价仍不作保证。

## M：读集×低信任返回内容，实际未来损害

320个真实应用单元：64开发+256验证。8个验证任务各2次重复，4条件×4方法；不是320个独立任务。另补64个仅改字段内容、保留其他字节/Token/EOS的控制。

验证集每个“方法×条件”有16单元：

- 当前读集、干净：四方法均16/16正确记忆，14/16正确答案。
- 当前读集、相干错误返回：OCC16/16安装错误记忆，实际后续模型消费，答案0/16正确。三种可信方法均16/16正确记忆、14/16正确答案；Strict 两方法各16次真实 fallback。
- 陈旧读集：OCC 正确拒绝，但16/16无当前记忆/任务未满足；三种可信方法真实重生成/回退并获得16/16正确记忆和答案。拒绝不等于交付了新状态。
- 内容-only64单元重复当前/错误返回结论，32次 Strict 的首个拒绝位置均在被改字段内，排除了排版线索。所有原始 P 神经 Z 与已有同输入控制一致，真实 DB/未来输入及 RevTrace16次 kernel 重放通过。

新增可归因任务损害为14/16（7/8任务），不能把干净条件已经错误的2例重复记为攻击导致。实际错误记忆则16/16。三种保护方法同效，不把正确 OCC 指责成有 bug，也不把组合内核称为独占验证算法。

主矩阵972次 GPU 模型操作中12次是开发控制，另160条 CPU编码消息不算 GPU。内容-only 再208次 GPU操作+64条 CPU编码消息；定义为逻辑生成/完整验证入口，非内部 CUDA kernel 数。开发集仍保留可信 Authority 选错 ID 的例子；证书不保证事实正确。

旧24单元已拆因：6例两层均正确，6例错误记忆/任务错误，12例正确记忆之后仍答错。原0.5B FP16回答器16次正确旧/新事实诊断只有1任务“当前对/旧错”、3任务两边错；早期1.5B FP32理想记忆16/16另列，未混成线上成功率。旧7B失败0完整/2调用保留。

| 主张 | 判断 |

## 自己的研究判断

现在最硬的增量是“版本正确仍可写入未经选择的内容，并可测地改变下一次神经计算与任务结果”，而非继续给 selector 起名字。历史选择修复定义了更完整的服务性质，但尚无成本独占优势；续写修掉真实浪费，同时迫使我们采用更强的替代基线。三者让原 C1/C2/C3 的证据与边界更清晰，不等于凭组合次数得到新算法胜利。

本轮应冻结：没有值得在这份银行上继续调权重、追漂亮数字的剩余门槛。下一批8来源只按元数据预留、未运行，且仅证明与已识别 CK5/N5清单不重叠；正式 held-out 声明前仍须全历史清单核查。后续是否扩大来源/并发，应由新的研究问题决定，而不是把当前低并发点写成容量主图。
