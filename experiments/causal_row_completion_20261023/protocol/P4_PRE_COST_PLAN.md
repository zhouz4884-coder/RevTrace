# Conditional Rescue feasibility, not implementation permission

This freezes the screen and conditional cost experiment before reading formal
effect estimates. No rescue job is started by the existing controllers.

1. Require the predeclared formal generic DGFT row-return benefit gate. If it
   fails,report the screen for diagnosis but do not expand this research branch.
2. Consider only actual `boundary-projection-mismatch` observations after a legal
   Canonical install. Do not use F2 labels or future fault identities online.
   For each such parent,the next independently defined fine frontier must be
   ahead of that parent and its audio must be released. Record the target even
   if the original safe rebase already met its deadline;those are not new gains.
3. Intersect parent-knowledge time,audio-release time,the unchanged2s Display
   deadline and an actual Authority-worker **lease** idle window. A model gap,
   unpolled result,drained peer or already executing job is not a free Worker.
   A gap ending at the next observed Authority enqueue is only an optimistic
   upper bound. Do not sum windows across an intervening occupied lease.
4. If no missed target has a positive window,NO-GO without a GPU cost probe.
   Otherwise deterministically rank potential recipes by largest positive window,
   then cell/source/parent identity. Use at most6distinct recipes,not a search
   for an audio sample with attractive ASR output. All recipes retain their
   original actual waveform prefix,legal new Parent,window/chunk semantics,
   precision,token budget and Trusted Render. Freeze recipes before calls.
   Refine this optimistic screen against actual per-session Private in-flight
   intervals before issuing any cost calls. A second overlapping Private
   generation is not allowed by the preserved single-flight contract. If the
   original fine window was already accounted,a later rebuild cannot rewind
   or double-count that progress record. These are additional safety/eligibility
   obligations,not resource slack that can be assumed away.
5. A conditional cost probe uses fresh FP32 generation in the singleton layout
   that the proposed idle-resource operation would actually execute. For each
   recipe run2same-input complete calls and one legal selected-output/Render
   check where applicable. It is at most12fresh generation calls,not a new
   serving matrix. A changed singleton physical layout is declared;no old Z is
   relabelled or CPU-reinterpreted as new-parent execution. These operator
   outputs do not automatically have Canonical write permission.
   If an Authority GPU would execute a private rebuild,physical placement does
   not change the Job's permission. Its declared private FP32 execution profile,
   Parent/Contract binding,versioned publication and resume semantics must be
   specified before any integrated prototype. Do not relabel it as the next
   Coarse Authority Job or consume the unreleased remainder of that interval.
6. Compare the **complete** paid preprocess+generation+Render/result time and
   repeat variation against the actual available window,with owner/IPC/WAL
   obligations and uncancellable work retained. Disagreement or insufficient
   slack is a failed gate,not permission to cut checks or shorten a baseline.
   A positive isolated cost result is only feasibility,not online Goodput.
7. No full new scheduling system follows automatically. An implementable rule
   must beat ordinary safe opportunistic new-parent generation and account for
   delayed future Authority work in a fresh same-resource control. If that rule
   is equivalent to the ordinary baseline or bounded evidence gives no strong
   opportunity,NO-GO for an independent algorithm increment. Keep the useful
   generic row interface separate from that decision.

No new GPU implementation/online comparison budget is silently added here.
