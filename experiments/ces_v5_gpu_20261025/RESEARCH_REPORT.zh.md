# CES V5 有界 GPU 实验与 CPU—在线执行差距审计

日期：2026-10-25。实验：REVTRACE-CES-V5-GPU-20261025。

## 结论

当前在线 V5 **没有通过 C2 性能升级门槛**。它保持了被测状态准入约束，
但没有获得优于强 Fine/Standard/旧 Cost-only 的可重复系统收益。
失败不能概括成“GPU 上预测不准”，更不能据此宣判前面讨论的完整算法失败：
**此次运行的是已实现的当前前沿原型，后继感知的完整版并未全部接入。**

最明确的实际缺口是：完整 common-cut 的剩余工作虽然被计费，却没有形成
跨重规划的服务承诺。同一合法目标可以反复留在未执行的第二批。
一个经两方独立核查的目标被后置13次，可执行后等待13.068秒，
自身完整行执行只需0.227秒。另一个缺口是在线目标没有包含已释放后继价值。
CPU 中已经发现并测试这类互补性，但符号模块尚未进入真实派发。

决策：当前原型作为论文新增性能贡献 **NO-GO**；围绕已观察缺口补齐闭环实现
和CPU验收 **GO**；修复后的GPU优势与独立新来源确认均 **尚未执行、尚未成立**。
不启动更大正式矩阵，不修改论文，不把NO-GO扩展成原C1/C2/C3架构失败。

## 2. 实现身份：CPU研究与在线算法不是同一完成状态

| 部件 | CPU/设计状态 | 本轮在线状态 |
|---|---|---|
| 实际Consumer ACK与残余Display/Commit信用 | 有测试 | 已接入 |
| 整批失败场景、逐行CDF与物理排空计价 | 有数学/等价测试 | 已接入，但行身份仍为交换性近似 |
| G/G、V/V、V/G等有限同构计划 | 有完整共同cut计费 | 已接入，每次只执行首批 |
| GPU0 deadline-order | 有退化分析 | 已接入排序消融，不是完整双GPU联合规划 |
| 已释放后继的期限回传 | 有独立符号模块与有限Oracle | **未接入** |
| 已知Verify成功投影下的后继合法启用价值 | 有设计与条件分析 | **未接入评分** |
| 旧目标跨重规划的服务义务/完成后缀保护 | 早期审计已提示需要aging边界 | **没有实现** |
| 全状态、全时域在线最优规划 | 不存在这种无条件证明 | 未实现，也不声称最优 |

因此，CPU中“可行/模型内最优”与GPU原型“获得系统收益”之间存在真实交付缺口。
运行前应更突出地说明这个分界。不能把未接入的模块计入已验证算法贡献。

## 5. 为什么CPU模型可行而当前GPU原型没有收益

### 5.1 计入后缀并不保证后缀得到执行：已取得真实见证

`choose_v5`对当前cut全部计费，但Owner只执行`plan[0]`。下一次空闲重新构造cut，
已承诺在第二批的工作没有保留状态，因而又能被新任务挤到第二批。
CPU审计指出的aging/有限窗口问题在在线实现中未解决。

独立原始轨迹抽核：`validation-staggered-mixed-progress_joint-r0`的
`authority-4-249`始终为Parent5、相同prompt、相同区间[160000,192000)。
Parent在12.909896s已安装，音频13s释放。14次实际GPU1空闲决策中，前13次都把它
放在完整计划第二批而不发；其中11次候选已就绪。第14次才派发，Strict通过，无Fallback。

| 不重叠分段 | 秒 |
|---|---:|
| 音频释放→合法Parent/目标就绪 | 0.000000 |
| 就绪→Enqueue | 13.068001 |
| Enqueue→Worker启动 | 0.003643 |
| Worker启动→完整行完成 | 0.226821 |
| 行完成→Trusted Render→发送→Owner收到 | 0.009956 |
| Owner收到→持久安装 | 0.031243 |
| 合计Commit latency | 13.339664 |

13.068秒包括其他批次的执行，不是空闲GPU，也不是可以免费回收的加速。
它证明了具体调度后置，尚不证明某个改法能同时保住别人的期限并提高整run Goodput。
见ACTUAL_TRACE_SPOT_AUDIT.md及其完整14次决策JSON。

错峰Progress有41/405条Commit>8s，其中34条在Enqueue前已过期；
Progress＋排序为56/405，其中49条已在Enqueue前过期。两者各另7条在派发后跨过期限。
这41条Progress的选中动作模型都已经给出Commit按时概率0；
排序版56条中54条为0。此处不是GPU意外超时才让模型失望。

并非全部晚行都由该行自身被后置：17/41、26/56在Parent成为可用时就已过期。
Progress晚行的均值路径含Parent等待6.795s、可用后排队2.673s、自身行执行0.497s；
前驱滞后与当前排队需分开追踪，不能当独立可加的“修复收益”。

### 5.2 CPU讨论中的后继价值没有接入在线目标

实际目标仍是一Session一个当前Authority target。自身Display过期就失去即时信用，
但完成它可能让已释放的下一前沿取得合法Parent。这种互补性需要后继义务或终端价值。
`deadline_backprop.py`在CPU模型中存在，Runtime没有调用它。
有限Oracle的完整调度/固定状态假设不能迁移成当前滚动原型的最优性结论。

### 5.3 模型只预测未来Canonical显示路径，遗漏仍在途的Private成功

真实Display是两条合法路径的最早实际应用：

`D_i=min(D_i_private_legal, D_i_canonical)`。

当前ACK正确描述已发生的Display，但尚未显示时，评分主要用Canonical行完成预测。
错峰Progress实际选中的Generate行中有45次，排序版有56次：在决策时Display尚未完成，
随后合法Private路径及时显示，而Canonical安装已经晚于Display期限，仍因Commit及时取得信用。
这表明当前目标预测确实漏掉一类真实路径；它不证明在线可完美预知这些Private结果。
也不能把Direct未知新P当作一定不兼容，给Verify制造独占保存优势。

### 5.4 CDF算对不等于目标身份与紧期限行校准充分

交换性行CDF可以算出正确的模型期望，却没有表达哪一行更慢、哪一行刚好紧期限。
独立CPU例在相同行时间分布下预测3 audio-s，真实构造的两种身份映射分别得4与2。
同期实际Generate行＋Owner P90覆盖：同步Progress约77.98%，Risk-cost约61.68%。
这说明某些条件校准仍不足；但不能拿不同策略选出的不同批证明一个动作的反事实遗憾。

同时，**V4的解释不能直接沿用**：错峰Progress选中的31个Verify物理批，平均预测
0.378558s、实际0.385068s，P90覆盖31/31；其Generate平均预测1.036883s、实际0.961116s。
部分均值已接近或偏保守，不能把本轮主要问题说成继续低估Verify Fallback。

### 5.5 真实动作和Host成本没有CPU正例中的免费优势

固定态探针同布局两次完整Z/P/text/stop/input一致；跨布局本次Z/P/text/stop一致，
但4行处理后输入身份都变化，因此不先验假设跨布局等价。
整4行批lease为0.959/0.882s，两个2行批为1.500/1.526s。
部分行提前返回，后组变晚，总代价增加。CPU正例的有利拆批成本不是本机普适事实。

错峰中位数：Fine 19个Authority批/19次模型调用，Progress 30批/32次调用，
Authority物理服务从21.359增至23.261s；Planner总wall从约0.00007增至0.668s。
Progress＋排序为30批/33次调用。已运行旧工作与两卡空闲功耗均计入。
这与滚动后置共同恶化整run，不能归因于一个单独新增开销数字。

同步Fine已经接近到达受限：忽略全部计算的Goodput上界为11.967，
相对实际Fine的中位理论余量仅5.95%；纯吞吐余量约2.70%。
错峰对应Goodput余量37.92%，主要仍是按时覆盖问题，纯吞吐余量约3.75%。
这些是到达时间给出的数学上界，不是可实现Oracle，也不是预测收益。

## 6. 怎样改进才值得继续：补齐同一C2，不换算法名字

下一候选应是**具有服务义务和已释放后继价值的双时间线闭环调度**，不是继续调整后代惩罚权重。

### A. 保留跨决策的真实任务义务

为`(session,epoch,Parent,frontier,contract)`保存最早可执行时间、被后置次数、
已欠的Commit义务和有依据的最晚启动估计：

`latest_start_i = dC_i - estimated_quantile_service_i - estimated_owner_delivery`。

允许重规划，但必须检查旧义务是否又被推出可行窗口；必要时预留一个经身份重校的完成动作。
预测分位数不是确定上界，错误预测不改变准入判据。不能盲目恢复Commit-first，
因为已有CPU反例证明那也会牺牲可获得的双期限Goodput。
性能风险预算/最小违约退路需要显式冻结，不能靠一个大权重掩盖取舍。

### B. 将后继期限回传真正接入Runtime

只对音频已释放、合法Private路径尚未满足且确需当前Parent的后继，形成义务集合U：

`effective_due(p)=min(dC_p, min_{q in U}(dD_q - estimated_remaining_service(p,q)))`。

这是排序/候选计划的信息，不是生成凭据。真实Child Job仍须等真实Canonical Parent生成并安装。
Verify成功的条件P可作精确兼容性分支；Direct/Fallback未知P必须保留不确定性，不能置为必然不兼容。

### C. 对完整双路径义务和有限前缀评分

保持实际信用：`g_i=a_i*1(D_i<=r_i+2)*1(C_i<=r_i+8)`。
在同一已释放义务集上评估已观察累计信用/时间与新增工作，例如有限视野的
`E[(Q_observed+deltaQ)/(T_observed+deltaT)]`，并显式约束/报告Commit风险。
这是有限视野预测，不是全服务全局最优。两条Display路径、完整lease和CPU/WAL成本均需进入模型。

### D. 必须先通过的验收

1. 原安全回归、旧CPU反例、新闭环反例全部保留；新规则在相同构造参数下不再无限替换旧后缀。
2. 任务Parent/epoch/contract变化、候选未就绪、WAL部分成功、重复收据和重启后重规划均fail-closed。
3. 后继传播须改变真实派发集合/次序；只重排同一16行批不算联合资源能力。
4. 对实际关键类型做同输入、同布局重复和付费合法Oracle，不从不同策略历史拼接新结果。
5. 下一GPU只做小型冻结对照：Fine/完整Standard、共享成本＋服务保护、
   服务保护＋后继回传、双路径完整版。共享执行器、成本校准和动作预算。
6. 先在复用诊断池完成实现，冻结参数后再用真正未参与本轮优化的新来源确认。

如果简单服务保护/EDF已经达到完整版全部收益，应保留有效的简单组合，并收窄独立规划贡献；
不能为了创新标签让强简单方法失去功能。若真实修复后仍不优于强基线，继续保留NO-GO。

## 7. 论文竞争力的具体落点

现阶段能写入研究记录的，是真实机制失败、精确原因和可证伪改法；不是新增性能headline。
只有补齐后的在线控制器在相同可信准入契约、相同质量及完整付费成本下，
减少这些实际排队/前驱传播损失，并优于共享保护与成本基线，才能升级为C2算法贡献。
原C1的状态权限边界和C3的恢复证据不因本轮固定rho=1原型失败而被抹除。
本阶段未改正文、摘要、标题或匿名镜像，也未运行新的恢复、Elastic rho、Grafting或KV复用课题。
