# N5 开发池阶段结论（不是独立验证结论）

原有 P0–P5 与用户新增任务全部保留。N1 已完成；N5 仍在推进。

## 实施的机制

五态降级控制器不改变可信 Authority 选择或 Canonical 安装谓词。
O（原始提供音频）、A（已同步记录的接收义务）、C（真实认证前沿）、
V（当前 Canonical 根上、实际 Consumer 已应用的合法可见前沿）分开。
所有音频期限以首次 episode origin 计算。R 为完整认证区间保留额度；
`sum(R-C)<=96 audio-s`，新输入经过真实 fsync 后才 ACK/派发。
只可放弃尚未发给 GPU 且已过显示期限的 Private 工作，不能取消实际在跑的
GPU Batch，也不能删除接收义务或给旧视图补上新认证覆盖。

## 我的判断与可证伪下一步

CDE的研究价值首先是将过载与恢复下的接收债务、认证进展和可见性承诺
分账，而不是把状态名字包装成新调度算法。单次c16的Goodput略高，不能
掩盖2s显示期限仍失败，或age-only明显下降。完整Standard获得同等控制器
后可以等效，是正控而非要排除的基线。

按验证前冻结规则，已选出32条新原生音频、32个与历史池不重叠说话人，
manifest=c58574c1...870dba6。独立测试将包含非饱和、近容量探针、突发、
有限持续过载、返回低负载和进程组故障/冷恢复，7个安全策略、3次配对。
若无法优于普通控制，新增算法性能贡献判NO-GO；输入债务恢复和诚实
认证可见性仍按各自证据报告，不转称全局独占机制。
