# 为什么本轮不把CDE升格为新的性能算法

这是完成105正式单元后的记录分析，不是新GPU试验，也不回调验证参数。
以下均为32独立说话人池、finite_overload同输入配对的三次fresh run。

|指标|完整CDE(r0/r1/r2)|完整Standard+公平限流(r0/r1/r2)|
|---|---|---|
|合法双期限Goodput|3.385/3.692/3.310|3.757/3.912/4.296|
|曾合法超前认证前沿的Private音频覆盖比例|.378/.299/.378|.657/.486/.615|
|未派发而过期的Private窗口|205/203/201|183/186/178|
|Display P99(s)|17.811/13.053/13.323|10.685/17.398/11.445|
|Commit-view P99(s)|17.811/13.053/13.323|11.314/17.398/11.596|
|CERTIFIED-ONLY进入次数|5/5/5|0/0/0|

直接成立的事实：CDE三次都减少了实际获得Private超前合法视图的音频，
也三次都退休更多未派发窗口；它没有取消已经执行的GPU工作，不能把
这些过期窗口都计成GPU节省。三次的P99变化方向并不统一，Goodput则均
低于Standard。全体方法最终认证音频前沿覆盖均为1；这是覆盖完整，
不等于逐词识别正确，更不等于整run双P99通过。

源码给出与记录一致的解释：达到critical age且存在未见的已接收债务及
Authority工作时，CDE转为CERTIFIED-ONLY；这个状态主动撤销Private，
暂停新的Private派发与新interval reservation，已有完整R允许继续填充，
Authority仍按原合法契约前进。因而安全/诚实的显示可以退回较迟的认证
时间线。它不会制造更多GPU容量，也不会让接近耗尽的期限重新开始。

这支持“更保守的可见服务动作有真实效用代价”的诊断，不是严格因果
证明每一项Goodput损失都由某一个mode造成：两策略的实际后续Batch/
Canonical/队列历史不同，不能把各重叠成本直接相加。原DGFT、queue和
age-only也全部保留；其中ordinaryqueue有时更好，不把它降格为错误基线。

所以结论是：五状态+输入债务+typed view机制已实现并通过记录内安全和
恢复核对；**新增反馈控制的独立性能优势NO-GO**。不根据这一批结果搜索
新阈值、重命名下一版算法，或只展示相对Fine的较好倍率。相对Fine的
部分Goodput/能量收益伴随不同WER，原C2的rate/waiting作用仍有修复后T1
独立因子证据，但不能借它宣称本CDE比完整Standard更强。

原始105条完整读数在N5_NORMAL_PRIMARY_v1.json；35组/30个配对对比在
N5_NORMAL_AGGREGATION_v1.json；所有32项CPU/IPC/WAL/energy/回撤读数的
三次原值与中位数在synthesis_data_v2。这里只解释已冻结的观测，不改
主指标、分母、成功门槛或历史NO-GO。
